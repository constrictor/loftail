# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

**M0–M8 complete, 2026-07-28.** The application is functional on Linux: it opens and indexes a log, filters and highlights it, tails it live, splits it into runs, restores its session, and autodetects a format. Directory layout is `src/core/` (UI-free, links QtCore only), `src/ui/` (Qt Widgets), and `tests/`; the commands below work and all CTest cases pass.

**M9 complete:** several logs open at once as tabs in a central document area; the side panes are the only dock widgets and cannot be dragged into it (`ARCHITECTURE.md` §12.2).

**Several logs asked for at once go through `MainWindow::openFiles()`, and three things about it are easy to undo.** It is the one funnel for the command line, File ▸ Open's multi-select, a drop of several files and several members picked out of one archive — which used not to agree, only the drop opening them all (`ARCHITECTURE.md` §12.2). `openFile()` returns **`bool` meaning "refused and reported", never "not there yet"**: a log that is merely absent opens a waiting tab and is a *success* (M13), so reading false as absence would put every waiting remote log into the failure list. Failures are collected and named in **one** message, because one message per failure leaves only the last one's reason on screen with the earlier files silently missing from the tab bar. And the loop must stay **non-blocking per address** (M17): it puts N tabs up at once, and anything that waits for one open before starting the next turns a command line naming ten unreachable hosts back into ten serialised connect timeouts before the window is usable. The parsing half is in `src/ui/CommandLine.h` rather than in `main()` solely because `main()` is unreachable from a test and `positional.first()` is exactly the kind of regression nothing would catch.

**A tab's label is decided for the WHOLE set of open logs, `src/ui/TabLabels.h` holds TWO rules, and the recompute rule is the trap.** Two logs called `app.log` used to produce two identical tabs differing only in their tooltip, which is what anyone tailing one service across two hosts or deployments has. `tabLabelsFor()` takes the open addresses and hands back one label each: the log's **bare** name, plus a bracket holding what tells it from its neighbours — device, then archive container, then the differing part of the path, joined `", "` (`ARCHITECTURE.md` §12.2). `prefixedLabelsFor()` beside it is the **older** rule — `logSourceDisplayName()` grown by the nearest differing parents, `svc-a/app.log` — kept for the recent-files menu, which is read against the other nine entries rather than the logs open beside it. Six things are easy to undo. The labels are recomputed **when the set of open logs changes** — `MainWindow::relabelTabs()`, after every context is pushed and after one is reaped — and cached in `DocumentContext::tabLabel`; compute one at open time instead and closing one of two `app.log`s leaves the survivor wearing a bracket it no longer needs, since nothing else in the window would ever revisit it. Nothing may recompute it from `updateTabTitles()`, which runs on every ingest tick of every log, and that function writes `setTabText`/`setTabToolTip` **only on a real change** — `QTabBar::setTabText` relays the whole bar out whether or not the text moved, which is the tab-bar half of the dock-title trap below. The tab rule groups on **`logSourceBareName()`, never the display name**: the display name brackets a host or container on *unconditionally*, so two hosts serving one path never collided at all and every solitary remote tab wore a host nothing was telling it from. An axis is spent **only where it raises the distinct-label count**, which is one test doing three jobs — it leaves the host out of a group that shares one (`app.log (svc-a)`, not `app.log (host-a, svc-a)`), it leaves a container out where the bare name already IS the container (`bundle.zip`, not `bundle.zip (bundle.zip)`), and it settles a group nothing can separate by letting them keep the shared name. The path run strips what **every** member carries off **both** ends and shows all of the rest, with an archive's two directory spaces stripped **separately** before being joined — concatenate first and a run can splice a directory outside one container onto one inside another. And a remote-shaped address that did not **parse** goes through `RemoteLocation::withoutPassword()` before it is split into segments: the old rule spent a bounded number of parents and the password stayed hidden only because the userinfo happened to be the leaf it dropped. The cost of the suffix shape is recorded rather than fixed — a name that already contains brackets can equal another group's label, where the prefix rule was structurally immune (the name was always the tail of its own label).

**Every address has a non-empty display name, that name is a SEGMENT and never a path, and neither half may carry a password.** `logSourceDisplayName()` was `QFileInfo::fileName()` at the bottom, which is `""` for `ssh://`, `/var/log/`, `/` and the empty string — and all 21 consumers showed the gap rather than the log: `Cannot open : …` in the refusal strip with nothing before the colon, a waiting tab wearing its `◦` and nothing else, `loftail — ` in the title bar, a blank clickable row in the recent-files menu. It now falls back to the deepest non-empty segment (`log` for `/var/log/`), then the scheme word for a remote-shaped address with nothing else (`ssh`, `sftp`), then `(unnamed)`. Four things are easy to undo. The fallback must stay a **segment**: `prefixedLabelsFor()` builds a recent-files entry as parent directories plus this string, which only works while the name is the tail of its own label — with the raw address `/srv/a/logs/` and `/srv/b/logs/` stop grouping and each entry carries a whole path (a menu is as wide as its widest item). **`logSourceBareName()` is the same name with the bracket taken off, `logSourceDisplayName()` is the two put back together, and the segment rule binds the bare half twice over** — it is `tabLabelsFor()`'s grouping *key*, and a key with a path in it groups nothing with anything. That is exactly what a **remote** address with no file-name part did until M-tablabels: `plainDisplayName()` fell back to the whole remote `loc->path` where the local branch falls back to `tailName()`, so `ssh://h/var/log/` answered `"/var/log/ (h)"` — a display name with two separators in it, contradicting this very paragraph for as long as it has existed, because `tst_remotelocation::everyAddressGetsANonEmptyNameAndNoNameIsAPath`'s table had **no remote row** and nothing else ever asked. It has one now, plus `ssh://h/` and the archive shapes. A **remote-shaped address that did not parse never goes through `QFileInfo`**, because a pathless URL's last component is the whole userinfo: that is how `ssh://deploy:hunter2@web1` put a password on screen. And the password rule itself had only ever applied downstream of a **successful** `RemoteLocation::parse()`, which is where a URL password is dropped — an address parse *refuses* is shown verbatim, so `RemoteLocation::withoutPassword()` is now the one filter that the name half, `logSourceDisplayPath()` and `LogSourceFactory`'s "Not a valid remote log address: %1" all ask. `tst_hostbookmarks::aPasswordNeverLeaksIntoAPathString` had asserted the rule since M11 over parseable URLs only, which is exactly the gap it fell through; it and `tst_remotelocation::anAddressThatDoesNotParseStillLosesItsPassword` now cover both.

**M10 complete:** highlight rules match on the same five axes as filters — subsystem, thread, priority, time range and message text — through one shared `MatchCriteria`/`FilterSet` predicate and one shared `AxisEditor` widget. See `PLAN.md` M10.

**M11 complete:** logs on other machines open over SSH, written `ssh://user@host/path` and accepted anywhere a path is. A remote log is fetched forward into a local spool and read back through an ordinary local source, so the paint path is unchanged and tailing works exactly as it does locally (`ARCHITECTURE.md` §6.3). libssh2 is the project's first non-Qt dependency and is **optional** — auto-detected, never required; without it everything still builds and a remote open explains that support is not compiled in.

**M12 complete:** compressed and archived logs open directly — `.gz .bz2 .xz .zst`, zip, tar and every compressed tar — as a **second fetcher behind the same spool** M11 built (`ARCHITECTURE.md` §6.4). An archive is a file *type* and SSH is a *transport*, so the two compose: the archive fetcher's input is an ordinary `LogSource`, which for a remote container is the SSH spool, and `ssh://host/var/log/app.log.1.gz` chains the two with neither knowing the other exists. Addresses continue through the container (`bundle.tar.gz/var/log/app.log`), so no new scheme and no session schema bump. Expansion is ordinary live ingestion — records appear as they expand — and then the stream genuinely ends: `LogSource::isComplete()` (non-pure, false by default, exactly the route `wasReplaced()` took) stops the watch, with no user-facing mode and the follow control untouched. libarchive is optional and auto-detected, gated exactly as libssh2 is.

**libarchive, unlike libssh2, IS exercised in CI.** The archive layer needs no network, no credentials and no disposable remote path: `tst_archivefetcher`, `tst_archivetail`, `tst_archivemembers` and `tst_archiveopen` build real `.gz`/`.xz`/`.zip`/`.tar.gz` files at runtime with libarchive's own write side (`tests/ArchiveFixtures.h`), and nothing binary is committed. `tst_archivelocation` and `tst_complete` are **ungated** and run in every configuration, because the path layer and the completion contract must behave identically with and without the dependency. The caveat below about M11 does not carry over to M12.

**The SSH socket must not stay a `QTcpSocket`.** `SocketDetach.h` duplicates the connected descriptor and lets Qt close its own copy, because a `QTcpSocket` keeps a read notifier armed and any Qt event loop then drains the socket into a buffer libssh2 cannot see — which surfaces as libssh2's "Timed out waiting on socket" after a *successful* login. The two event loops that did it are the modal password prompt and the main window's own. `tst_socketdetach` pins it, ungated.

**A server that refuses SFTP falls back to shell commands over an exec channel** (`ARCHITECTURE.md` §6.3.1). `SshSession` has two modes; `SshFetcher` and everything above it are unchanged because both modes answer the same five operations. **The fallback is chosen by probing, never by reading libssh2's error code** — a server that accepts the subsystem channel and then has no `sftp-server` behind it (a generic sshd config on a stripped-down embedded image) makes libssh2 wait for a version packet that never comes and report a plain `LIBSSH2_ERROR_TIMEOUT` after a *successful* login. Treating that timeout as transient locked out exactly the servers the fallback exists for. The code is consulted only after the probe has also failed, and only to decide whether a retry is worth anything. SCP was considered and cannot work — no reads at an offset, no re-stat, no handle to `fstat`. `SshExecCommands` and `ExecSizeProbe` are **always compiled** although only the gated transport uses them, because `shellQuote()` is a security boundary (a remote path reaches a command line) and the ladder is the only decision the transport makes; either compiled in a single configuration is tested in a single configuration. `tst_sshexec` and `tst_execsizeprobe` are ungated and run the generated commands through a real `/bin/sh` against real files.

**M16 complete: reading a remote log and measuring one are separate questions, and only the first has one answer.** Reading is `tail -c +N | head -c L`. Measuring was `stat` — the utility a stripped-down embedded image leaves out, on the very same boxes whose sshd refuses SFTP — so it is now a ladder settled per server: `stat` (O(1), the only rung with an mtime), then `ls -lnLd` (O(1)), then `wc -c <` (**O(file size) per poll**, and fenced accordingly: it will not settle above 8 MB, clamps the poll to 15 s, and errors past 64 MB, because invariant #5 is not something a status-bar note buys off). A rung is settled **behaviourally** — a size is believed only after `readAt(size − 1, 1)` delivers a byte, which is also the only proof that non-POSIX `head -c` works on the box.

**Five M16 rules that are easy to undo by accident.** `SshFetcher::pollOnce()`'s `mtime == kUnknownMtime` branch must come **before** the `mtime > m_lastMtime` one — `-1 > -1` is false, so falling through switches rotation detection off in silence on exactly the servers that need it. `ExecSizeProbe`'s read seam must bind `Impl::execRead`, **not** the public `SshSession::readAt`, which gates on `execFileOpen` — a flag not yet set while settling, so going through it would reject every rung and disable the fallback entirely. The proof accepts `>= 1` byte and skips the read for a zero size, because a log **grows** between the query and the read: only over-reporting is detectable, and requiring exactly one byte would reject correct rungs on any busy log. The ladder re-settles on **every** `openFile()`, so a rotation gets a fresh choice — settling once per session lets one unparseable `ls` line strand the tab in "waiting" forever. And the stall timer is restarted only when a compare actually runs, never on growth: a bursty log alternates growing and stalling, and resetting on growth fires the 4 KB compare every other poll.

**Nothing in CI exercises libssh2 beyond linking.** The transport's own paths — handshake, host-key verification, agent/keyboard-interactive auth, and whether a real `sftp-server`'s FSTAT follows the handle — are covered only by `tst_sshlive`, which skips unless `LOFTAIL_TEST_SSH_URL` names a disposable remote path. Everything above `RemoteFetcher` is covered without a network by `tst_spooledsource`, `tst_remotetail` and `tst_remoteopen`, using `tests/FakeFetcher.h`. When changing the SSH layer, run `tst_sshlive` against a real host by hand; a green pipeline means nothing about it.

**M17 complete: opening a remote or archived log no longer blocks the thread that opens it** (`SPEC.md` §3, `ARCHITECTURE.md` §6.3.3). `SourceFetcher::start()` used to connect, authenticate, prompt and fetch 128 KB — and for an archive, decompress a container until it reached the named member — before returning; only then did it start its worker. That froze the window per log, and at startup froze it before there was one, because `restoreSession()` runs in the `MainWindow` constructor ahead of `show()`. `start()` now publishes `Connecting`, spawns the worker and returns, and **M13's waiting state carries the rest with almost no new machinery**: a not-yet-connected spool is a log that has not turned up, one step earlier. Measured against a black-hole address: window up immediately, quit in 107 ms, both previously bounded by the 20 s connect timeout.

**A refusal now keeps its tab** and reports the transport's own words, because the tab is on screen before the far end answers and a tab that appears and vanishes is worse than one that explains itself. Only what can be decided with **no I/O** still fails an open outright — an address naming no host, an archive naming no member, a dependency not built in, a cache directory that cannot be created.

**Those no-I/O refusals report into a message strip above the document well, NEVER into the status bar, and `reportOpenRefusal()` is the single funnel.** They are the only opens that make no tab, so they are the only report with nowhere of its own to live — and `m_statusLabel` is the one place it must not be, because `updateStatus()` rewrites that label from the active document on every ingest tick and every tab switch, so beside one live log a reason written there is gone within a second (found as improvements #16). The strip (`openNotice`/`openNoticeText`/`openNoticeDismiss`) is dismissible and nothing else takes it away. Four things are easy to undo. A gesture is bracketed by `beginOpenBatch()`/`endOpenBatch()` and the bracket **nests** — `openFile()` opens an archive's picked members through `openFiles()` — so only the outermost close renders, or picking three members produces three messages. `restoreSession()` is bracketed **too**, and `prepareContext()` takes an out-parameter for the reason: without it the restore lists paths and drops every "why", which is the half worth reading. A render **replaces** and clears the pending list, which is the whole of "it does not accumulate" — nothing appends, so do not "improve" it into a log. And a `QMessageBox` is not available for this however tempting: `restoreSession()` runs in the `MainWindow` constructor **before `show()`**, so a modal there is a dialog over no window and a session of several unreachable logs is a stack of them.

**Six M17 rules that are easy to undo by accident.** `LogSource::notReadyYet()` is asked **on bytes, never on a state change**: `Document::resume()` clears the waiting flag unconditionally and opening a spool never fails, so a resume with nothing to read settles the format against an empty sample, leaves it unsettled forever, and leaves the only state from which the settling path is reachable — killing autodetect, the format dialog and format persistence, silently. It **excludes `Live`**, so an empty remote log opens as an ordinary empty tab rather than wearing a `◦` that says "not there yet" about a log that has been found and read. And it is consulted in **exactly two places** — `Document::prepare()` and `LiveController::checkWhileWaiting()` — never in `checkNow()`'s vanish branch, where merging it with `originVanished()` blanks the view on every slow-link rotation once the 2 s grace expires. The **prime is published all at once**, because the format *and* the encoding settle from the first committed bytes and both libssh2 and libarchive may return short reads. **Nothing joins a fetcher**: `~SourceSpool` retires it to a reaper instead, or closing a tab on a host that is not answering waits out the connect — and once a worker can be blocked on the application thread for a password, that wait is a deadlock. And the **keychain rung does not move** despite the read now being marshalled: `authenticate()`'s `!prompter` bail is about whether a *person* is there, not which thread is running.

**A prompt travels to the application thread rather than the auth ladder being restructured**, because keyboard-interactive is a conversation libssh2 drives through a callback with the server's own wording per prompt — fail-ask-retry cannot express it. `GuiCallGate` is the one primitive and the only place its discipline is written down; `PromptRelay` and a marshalling `SecretStore` sit on it. One gate for the process, so "one question at a time" is true by construction. Two things that were quietly broken and are now not: **File ▸ Reconnect** could never clear a password-needed refusal (it poked, and the retry ran unattended with nobody to ask, and re-latched), and **"Skip This Host" skipped the file**, so the next file on that host asked again. Serialising the connect per target (`SshConnectHold`) is what keeps "one prompt per host" true now that connects run in parallel — it used to fall out of their all being on the GUI thread.

**`tests/FakeFetcher.h` cannot prove the milestone** and says so: a fake returns from `start()` instantly, which satisfies the blocking contract exactly as well as the non-blocking one. `tst_asyncconnect` uses a transport that genuinely takes a second and is the test that actually pins it — open returns without running a 2 s connect, closing a tab mid-connect without running out a 5 s one, and quitting mid-connect does not hang. Both budgets are one **deliberately loose** second (`kNonBlockingMs`): the claim is only that the connect did not run, a regression fails it by the whole connect, and a wall clock on a shared CI runner is competing with every other job on the box — at 250 ms it went red at 543 ms with the code correct.

**M13 complete:** a log that is not there is a **state, not an error** (`SPEC.md` §3 "Logs that are not there", `ARCHITECTURE.md` §6.5). A path that does not exist yet opens a waiting tab and starts reading when the log turns up; a log deleted while open clears to the same state and comes back when it does; an unreachable SSH host opens and reconnects in the background. Waiting lives on the **live seam**, not in a fourth `LogSource` — what changes is not how bytes are read but whether there are any yet, which is `LiveController`'s existing question. The one asymmetry to keep straight: a waiting **local** document releases its source, a waiting **spooled** one keeps it, because the source owns the spool and the spool owns the fetcher that is retrying. Only genuine refusals still failed to open — a malformed address, an archive naming no member, a changed host key, a rejected password, a dependency not built in. **M17 narrowed that list to the ones decided with no I/O**: a changed host key and a rejected password now keep their tab and report it (see M17 above).

**Two M13 details that are easy to undo by accident.** `originVanished()` is checked **after** `wasReplaced()`, and only after a **2 s grace period measured in elapsed time, not in checks** — the filesystem watcher fires checks too, and a rotation produces a burst of them at exactly the moment the path is briefly empty, so a count-based grace period would blank the view during a `logrotate`. And `BufferedLogSource::originVanished()` deliberately does **not** go through `pathIdentity()` — originally because the Windows stub returned 0 for everything and would have reported every open file as vanished on the first tick, and still now that the stub is gone, because **0 means unknown**: a file that is gone, a file that will not open and a volume with no usable index all answer alike, and only the first is a log that is not there. `QFileInfo::exists()` asks the one question, and costs an attribute query rather than an open on a path walked every tick.

**The waiting reason is REPUBLISHED, never only announced — and an empty one is never published.** `waitingChanged(true, reason)` fires on the transition, which was sufficient for M13 (a local wait's reason cannot change while it is true) and wrong for every spooled log since M17: the tab is on screen *before* the far end answers, so the wait begins on `connecting…` and the real reason — refused, host down, an archive holding no such member, an SFTP subsystem that timed out — arrives on a later tick, with `SshFetcher` restating itself several times over one wait. Only the status bar tracked it, so a refused archive member sat under `connecting…` in the view and in its tab tooltip for the life of the tab, with no network anywhere. `LiveController::checkWhileWaiting()` now calls `republishWaitReason()` beside `publishSourceStatus()`, and four things about it are easy to undo. **An empty reason must never be published**: `sourceStatusText()` is empty for a local source *always* and for a spooled one in every healthy state, and `MainWindow`'s handler writes what arrives straight into `LogView::setPlaceholderText()` — so an unconditional re-emit blanks "app.log has not appeared yet — waiting for it" on the first tick of every locally-waiting document, which is `tst_waitingremote::aLocalWaitKeepsTheReasonItWasGiven`. The guard compares against **`Document::waitReason()`**, the string actually on screen, and not against `publishSourceStatus()`'s `m_lastStatusText`, which `start()` latches before anything has compared it to the reason `prepare()` stored — piggybacking on that one silently skips the first correction, the only case this exists for. It must **not** route through `beginWaiting()`, which brackets a `clearIndex()` in a model reset and resets the vanish timer: a model reset per reason change drops every view's anchor and selection while nothing about the visible set has moved. Hence `Document::restateWaitReason()`, which writes `m_waitReason` and nothing else — not the index, not `m_lastError`. And the signal now carries `true` twice running, so a receiver must read it as "here is the current sentence" and not as a transition; the doubled `"connecting…  |  The archive holds no member…"` status line then collapses for free, because `updateStatus()` joins reason and status only when they differ. `tests/FakeFetcher.h`'s `refuseWhileWaiting()`/`restateWait()` are what express a reason that changes *after* the transition — the fake's other refusal publishes synchronously from `start()`, which is why `tst_remoteopen::aTransportRefusalKeepsTheTabAndSaysWhy` passed throughout.

**A format and an encoding are judged against REAL BYTES or not at all, and "the file exists" is not that** (`SPEC.md` §3, `ARCHITECTURE.md` §6.5). A local wait ended on existence and settled everything on the spot, so a log created by a service that had not logged yet — the ordinary state of one, and the very file somebody opens to watch it start — had its format compiled and its encoding detected from a sample of nothing, once, for ever: `Document::resume()` is a one-way door and `openAndSettleFormat()` had no other caller. The format half merely mis-annotated the log and latched "format not recognised — File ▸ Preferences…" over a table whose every column then parsed perfectly; the **encoding** half made a UTF-16 log unreadable for the session. Four things are easy to undo. The cut is at the **decision, not at the resume**: waiting still ends on existence, because the spooled transport can tell "have not asked yet" from "asked, and it is empty" (`notReadyYet()`) and a local `stat` **cannot** — a file created a millisecond ago and one that stays empty for ever are byte-identical, so requiring bytes to leave the wait puts `◦ has not appeared yet` under a file anyone can see. `formatSettled()` is what carries "not judged yet" instead, and it is now read on the local path too. The settle re-enters through the **same `resumeRequested()` signal** the wait uses, never a second one — the owner's answer is `Document::resume()` in both cases, and a second wire is a wire to forget, which would settle the format against the empty sample after all. `LiveController` asks it in **two** places and both are needed: `checkNow()` on the **size, not on growth**, and `start()` **before `syncBaseline()`** and through **`refreshSize()`, never `size()`** — the initial scan runs on a worker while a spool fills, so the whole of an archived log can land before the watch begins, and a source asked for its latched size answers 0 about a log every record of which is already indexed (`tst_archiveopen::theFormatAndTheSessionRememberAnArchivedPath` is what fails on that one). And **every judgement above it is gated on the same flag**: `openWithSettings()` defers the prompt for `isWaiting() || !formatSettled()`, which is what stops `: > empty.log; loftail empty.log` raising Preferences over "No sample lines to preview." with Detect greyed out and then refusing the open when it is cancelled; `resumeOrSettleDocument()` runs its persist/ask/report block only when the resume actually settled something, so a resume with nothing behind it consumes no owed dialog and latches no notice — which is the whole of the background and session-restored case, where nothing is asked and the notice was the only thing the user ever saw.

**A rotation is no longer silent, and the trap is that `wasTruncated()` does not mean the file got shorter.** A log replaced or truncated behind the application now says so — `statusBar()->showMessage(..., 5000)`, the transient channel `announceLogFontSize()` established, never `m_statusLabel`, which `updateStatus()` rewrites from the active document on the very tick this fires from (`SPEC.md` §3, `ARCHITECTURE.md` §6.5, §12.2). `LiveController::ReloadCause` is derived in `checkNow()` from `wasReplaced()` and a shrink against `m_lastSize`, and **never read off `wasTruncated()`**, which is a catch-all: `MappedLogSource::refreshSize()` latches it for a shrink, an identity change *and* an in-place rewrite the `HeadWitness` caught, so classifying on it announces "was truncated" about a log that **grew** — the case `tst_tail::overwriteInPlaceTriggersRescan` builds on purpose. Seven things are easy to undo. There are **two causes and not three**, because `SPEC.md` §3 already rules that "rewriting a log in place counts as replacing it". `replaced` is tested **before** the shrink: a rename-and-recreate rotation almost always lands a *smaller* file at the path, so the other order calls nearly every real rotation a truncation. The no-source branch passes **`Retry` and announces nothing**, since it runs every tick until an unreadable log becomes readable, and only a rescan that **succeeded** announces at all. `reloaded` is emitted **before** `rescanned()`, which must stay the last statement of `doRescan()` — being last is what makes handing control to eight subscribers safe with no `QPointer` dance (contrast `settleFirstBytes()`). The new signal sits **beside** the nullary `rescanned()` rather than differentiating it, because that one fires for the reload *and* both resume paths and eight test files connect to it with argument-less lambdas; that those lambdas still compile and still fire is the only evidence the seam stayed inert, so every `tst_tail` case asserts on both. The handler is **below** `ctx != activeContext()`, the opposite of the M19 tab marker directly above it in the ingest handler: a marker waits on a background tab until it is looked at, a passing sentence cannot, and there is one status bar. And `announceReload()` **returns early when the same sentence is already up**, so a writer rewriting in place faster than 5 s cannot re-arm the timer forever and keep the record count hidden. A **spooled** source answers `wasReplaced()` for all three shapes, so `Truncated` is unreachable remotely — stated in `SPEC.md` §3 rather than left to be found.

**A waiting spooled document keeps its SOURCE, and an archive with no container had none — which is how a local archived log opened before its container existed waited for ever, including after the container appeared.** M13's asymmetry (above) is the invariant: a local wait releases its source, a spooled one keeps it, *because the source owns the spool and the spool owns the fetcher that is retrying*. `ArchiveFetcher::start()` broke it by returning false when `openContainerSource()` found nothing there, which destroyed the spool with it — so `Document::prepare()` fell into its **source-less** waiting branch, where nothing was retrying and nothing could be: `resume()` opens `OpenPolicy::Reuse` and `openSpooled()` will not *create* a spool under `Reuse`, so ~80 resumes a minute failed against an empty registry for the life of the tab. `Reuse` is right and must stay — it is the promise that a watch tick never becomes network work, shared with `reopen()` and `reformat()`, and File ▸ Reconnect is the deliberate gesture for the other thing — so the cut is at `start()`, which now publishes `Waiting`, spawns the worker, and lets `awaitContainer()`'s loop (which existed and was unreachable without an input) retry `openContainerSource()`. It is not multi-member-specific: a bare `.gz` with no member spelled at all hit it too. Six things are easy to undo. The retry is keyed on `logSourcePresence() == Absent` and **never on the open merely having failed** — an unreadable container is a **refusal that keeps its tab and says why** (M17), because a permission is not something to poll for eighty times a minute, and `start()` returns **true** for it so that the tab survives to say so. The retry is **local-only**, gated explicitly on `RemoteLocation::isRemote()` rather than left to fall out of `logSourcePresence()`'s remote optimism, because it runs on the worker and re-opening a remote container would reach `SourceSpoolRegistry::acquire()` off the GUI thread; a remote container's open can only fail for no-I/O reasons anyway, and those still fail outright. The waiting reason names the container through **`QFileInfo::fileName()`, not `logSourceDisplayName()`** — a container path is itself an archive address, so the display name strips a single-stream suffix and would say loftail is waiting for `app.log` when what is missing is `app.log.gz`. With a source present again, **`republishWaitReason()` starts working for free** (it returns immediately when there is none), so the sentence tracks the fetcher instead of freezing at the transition's. `logPathIsWellFormed()` now answers **false for an archive address that `needsMember()`**: that is pure string work, so it is as decidable before the container exists as after, and answering true turned M17's no-I/O refusal into a wait the container's arrival could not end. And `LiveController::checkWhileWaiting()` now writes a throttled diagnostic line when a resume **declines while `back` said yes** — the state this bug lived in wrote *nothing at all*, since a true `back` skips the "still waiting" line and the owner's `if (!ok) return;` is silent, which is exactly what `SPEC.md` §"Diagnostics" says will not happen.

**"Not there" and "there and shut" are different sentences, and `logSourcePresence()` is the one place they are told apart.** `plainAvailable()` folded `exists()` and `isReadable()` into one bit, so a log whose mode is `000` was described as one that "has not appeared yet" — a file the user can see in their file manager, reported as missing, with nothing on screen to correct it. Both still **wait** and both still recover on the tick, because a permission is granted as readily as a file is written; what moves is `WaitCause`, which gained `NoAccess`, and `waitCauseFor()` is the single funnel that picks it (`prepare()` passes `NotYet`, `reopen()`/`reformat()`/the vanish branch pass `Gone`, and an unreadable log overrides both). It stays **optimistic for a remote address** — `Present`, always, never `Unreadable` — for the reason `logSourceAvailable()` always has been: the honest answer costs a round trip and this runs during session restore. `logSourceAvailable()` is now just `logSourcePresence() == Present`.

**M14 complete:** a remembered SSH password goes to the **OS keychain** where one will answer — KWallet or GNOME Keyring through the freedesktop Secret Service, the Windows Credential Manager, the macOS Keychain — through one always-compiled `SecretStore` seam in core with QtKeychain behind it (`ARCHITECTURE.md` §6.3.2). The plain-text `hosts.json` fallback is unchanged in shape, schema and containment rules and still applies where there is no keychain, off by default and naming the file before the box can be ticked.

**Three M14 rules that are easy to undo by accident.** `available()` is a **round trip, not a link check** — `QKeychain::isAvailable()` on Linux is true as soon as `libsecret-1` can be `dlopen`ed, daemon or not, so a headless runner and a KDE box with `kwalletd` stopped both pass it; a real read decides, where `EntryNotFound` is the *success*. `rememberSshPassword()` **never falls back to the file once `available()` said yes** — a keychain that refuses yields `Failed` and is reported, because the checkbox named its destination before it was ticked; three ungated tests assert it. And the keychain rung sits **below** `authenticate()`'s `!prompter` bail, because a keychain read can raise an unlock dialog and `reconnect()` runs on the fetcher thread with no one to show it to.

**M14 also connected two wires that had been dangling since M11**, both on this path: `SshSession` filled in `askPassword()`'s `bool *remember` and never read it, so ticking the box had never persisted anything; and `HostBookmarkStore::find()` had **zero call sites in `src/`**, so a bookmark's saved password was written and never read back at connect time. If either regresses, "remember this password" silently stops working while every test above the seam still passes — which is why `tst_sshcredentials` drives the real `MainWindow::openFile()` for the second one.

**Nothing in CI exercises a real keychain either, and nothing can** — the runners are headless with no session bus, so no backend would answer. `tst_keychainlive` is gated twice like `tst_sshlive` (not built without QtKeychain; skipped unless `LOFTAIL_TEST_KEYCHAIN=1`, because it writes to the developer's real keyring). Everything above the backend is ungated and driven through `tests/FakeSecretStore.h`. The AppImage additionally **cannot bundle libsecret** — QtKeychain `dlopen()`s it, so `ldd` never sees it — so inside the AppImage a host without `libsecret-1.so.0` gets the plain-text path and is told so.

**M15 complete:** a filter now keeps **context** — N records either side of every match, dimmed, which is `grep -B`/`-A` (`SPEC.md` §6 "Context", `ARCHITECTURE.md` §7.2.1). It is not an axis and not a `FilterSet` field, because it is not a property of a record: whether row *r* is shown depends on rows *r±N*. So it is two ints on the `Document` and one forward pass (`ContextEmitter.h`) shared by `applyFilters()` and the live append, with one byte per visible row recording "context, not match". Everything below it is untouched — `FilteredIndex::setVisible()` already took any ascending ordinal list and rebuilt its own prefix sums, so every geometry path, exact and estimated, runs over the widened subset without knowing.

**Context widens the MESSAGE-TEXT axis and only it, and the whole rule is which way the predicate is cut.** The emitter's `inBound()` is `Document::inContextStream()` — the run bound plus every *non-text* axis, integer comparisons only — and its `matches()` is `Document::matchesTextAxis()`. Their conjunction is `acceptsInView()`, so context at 0 changes nothing anywhere. Two user-visible facts then fall out of the cut rather than out of code, which is the point: a context record always passes the other filters (`-B 2` under a WARN floor gives the two nearest WARN-or-worse records, stepping over the INFOs), and **an inactive text axis makes context inert with no gate** — every in-bound row is a match, so nothing is left to be context to. That is what lets `FilterPane` hand the two spinners to `AxisEditor::addTextExtra()` and let a checkable group box grey them out; there is no enable flag anywhere to fall out of step.

**Four M15 rules that are easy to undo by accident.** "Either side" counts **in-bound records, not ordinals** — with a metadata axis active the stream has interior holes of any width, so the leading window is a backward walk from the match (stopping at `lastEmitted`, which is what keeps it O(n) over a scan) and the trailing window is `ContextState::sinceMatch`, never `r - before` or `r - lastMatch`. Leading context is still a **tail append, never a mid-list insert**, but now because the walk stops at `lastEmitted` rather than because the bound is contiguous — the constraint run selection used to carry for context's sake is gone. In the live path the **pop point and the re-scan start must be the same row**, and that row is `Document::contextWindowStart(base, before)`: `base - before` stops short of the window under any metadata filter and leaves orphaned dimmed rows behind a match that is no longer there, and restarting the scan at `base` instead drops any match inside the popped window permanently and silently. And the pop widens **only when the provisional record's match status actually flips** — otherwise every tick that grows a trailing multi-line record churns the whole window instead of one row and jolts a detached reader's scroll position.

**The Filters pane is laid out for height, and several of its habits are load-bearing.** **All five** axes are a **checkable `QGroupBox` whose title row is the enable control**, which is what removed the "Filter by <the axis name>" checkbox that repeated every title. Consequently `AxisEditor`'s enable controls are `QGroupBox *`, `m_priorityEnable` included — priority was a bare checkbox and combo on a row of its own until it became a section like the rest, and two special cases went with it: the one axis that did not look like an axis, and the hand-written `setEnabled()` that stood in for the greying Qt does for a checkable box. And the time editors carry `QSizePolicy::Ignored` plus an explicit `setMinimumWidth` — a plain `setMinimumWidth` below the size hint does nothing, because `qSmartMinSize()` takes `minimumSizeHint()` and only ever *expands* it to `minimumSize`; without the policy the one-line time row alone sets the pane's minimum width to ~394 px and puts a horizontal scrollbar under an ordinary dock, with the value lists' All/None/Invert buttons the first thing off the edge. Every widget the tests reach for now has an **object name** (`priorityGroup`, `messageGroup`, `subsystemList`, `subsystemNarrow`, `subsystemAdd`, `contextBefore`, `clearFilters`, …) and no test in `tests/` finds a filter widget by its visible text any more — `tst_highlighterpane` did, for a `QPushButton` reading "Add", which the embedded `AxisEditor` also had until construction order stopped being the tiebreaker. **The one thing in the pane with no object name is the "Others" row**, because it is a `QListWidgetItem` and not a widget: it is the discovery rule that used to be a "New" checkbox beside the list and is now row 0 of the list itself (`ARCHITECTURE.md` §7.2). Tests find it by `AxisEditor::kOthersRole`, never by its label — which is translated prose — and count values from `AxisEditor::kFirstValueRow`, because `list->count()` is now one more than the number of subsystems.

**Height was squeezed out of the axes themselves, and `setCollapsible(true)` — briefly borrowed from `HighlighterPane` — was tried and REVERSED, first here and then in the pane it was borrowed from.** Hiding a switched-off axis's body made the Filters pane unreadable, because what an axis offers is most worth knowing *before* deciding to use it and the user had to switch a filter on to find out whether it was the one they wanted — and that turned out to be just as true of a highlight rule, so `setCollapsible()` no longer exists at all. A *different* question — what becomes of an axis this log's format cannot fill (no `%t`, no `%d`) — was briefly a per-pane flag (`setHidesUnsupportedAxes()`, hide in `HighlighterPane`, grey-with-the-reason-in-the-title in `FilterPane`) and is now settled the same way in both: **left out entirely**, flag deleted (`ARCHITECTURE.md` §7.2). Being switched off is a state the user can undo, so its controls are worth reading; a field the format does not carry is not, and a section that can only say "not available here" is read once and holds its space for the session. The `setEnabled(false)` in `setDocument()` is separate and stays — it is what keeps a preset or restored session from putting an unfillable axis into force where nothing on screen could take it back out. Every axis the format does carry stays expanded in both panes: Qt greys a checkable group box's body, which says "not in force" without moving anything, and the `QScrollArea` absorbs the ~666 px the five expanded axes want. The real height savings stayed: the message axis spent four rows on three checkboxes and a context row (now one row of `.*` / `Aa` / `≠` toggles plus the two spinners, via `addTextExtra()` which appends to that row rather than to the body), and each value axis spent a whole row plus a button on "Add … manually" (now the narrow field itself, with a `+` that appears while the typed text is not already listed). The glyphs are **not** translated and the words moved to `setToolTip` *and* `setAccessibleName`. **Nothing in `AxisEditor` is auto-raised**, `All`/`None`/`Invert`, `+` and the three message toggles alike — a frameless button with no icon reads as a caption or a legend, and the frame is what says "press this". The toggles were the one exception, on the argument that a checked state supplies the affordance instead; it does not, because it only tells someone who has already worked out that they are buttons which ones are on. Reversed on the user's report that they did not look like buttons, at no cost in width (`messageGroup`'s minimum size hint is 108 px either way).

**Two widths are load-bearing and were only latent while the axes collapsed.** With every body visible, the **message axis** became the widest thing in the pane at 308 px min — two four-digit context spin boxes ask ~70 px each — and the pane pays a width overrun in a horizontal scrollbar whose first casualty is the `All`/`None`/`Invert` column. The context spinners are therefore capped with a **`setMaximumWidth` and nothing else**, and the `QSizePolicy::Ignored` trick the time editors use **must not be added to them** — the two pull opposite ways and the combination shipped a row laid out on top of itself. A cap alone is already sufficient *and* already the whole mechanism: `QWidgetItem::sizeHint()` bounds the widget's hint by `maximumSize`, so the layout asks for 62 px rather than 71 and allocates exactly that. `Ignored` instead tells the layout the hint means nothing and to hand over every spare pixel; the capped widget cannot fill the oversized cell, `QLayout` **centres** it there, and each spin box drifts right out from under the glyph naming it and into the *next* glyph, while the last box is pushed past the row's right edge and clipped by the group box. A `setMinimumWidth` floor is still right and still needs no policy — `minimumSize` wins over the hint in `qSmartMinSize()` regardless. Message and Time range now sit at 289 and 288 px, so neither is the outlier. `tst_filterpane::theContextRowLaysOutWithoutOverlapOrClipping` pins it by asserting on the child **rectangles** at five dock widths, because every widget in the broken row still existed, still held the right value and still answered `isVisible()` — only its geometry was wrong, which is invisible to every other kind of test.

**The context spinners are labelled `↑` and `↓`, and were `−` and `+`.** Both arithmetic signs were wrong twice over: a minus abutting a numeric stepper reads as *decrement* and a plus as *increment*, which is the one meaning a spin box's neighbour must not carry — and `+` is **already a button in this pane**, the one that adds a typed name to the subsystem and thread lists, so the same glyph meant "add" ten pixels away. Before and after a match are, in a table scrolled top to bottom, literally above and below it, so an arrow says which records are meant without borrowing from arithmetic and at the same ~6 px. The glyphs are **not** translated (the labels are `QString::fromUtf8`, never `tr()`) and the words live on the spinners' `setToolTip` *and* `setAccessibleName`, exactly as the `.*` / `Aa` / `≠` toggles beside them do. The row's spacing is also set **per gap** rather than left uniform — 2 px binding each arrow to its own box, 8 px after the "Context" caption, 10 px between the two pairs — because a glyph equidistant between the caption and the box it labels binds to neither. Second, `AxisEditor`'s root layout is **not** flush — `setContentsMargins(6, 4, 6, 4)` — because a rounded group-box frame 0 px from the dock edge reads as a rendering fault, and both users put the editor in a frameless `QScrollArea` where nothing else supplies the gap.

**Three later changes to the Filters pane, each with one trap.** (a) **The axis order is Priority, Subsystem, Message text, Thread, Time range** — the message search moved *below* Subsystem, because the level floor and the subsystem list say which records are being read and a stream is picked before it is searched. (b) **The two value lists are the only things in the pane that grow**: each value axis is added to `root` with **stretch 1** and its list row to the axis body with stretch 1, and the **trailing `root->addStretch(1)` is gone** — that stretch is precisely what used to pin both lists to their floors while an empty gap grew under Time range, and re-adding one silently restores the old behaviour by competing for the same pixels. Both value axes take the **same** factor, so the split cannot shift under the reader as the scan turns up more subsystems. (c) **TRACE is dropped from the priority combo and the axis now ships OFF.** The trap is that `kPriorityByIndex` **must keep all six levels**: `MatchCriteria` persists `minPriorityIndex` as an index into it, so dropping its first row reinterprets every stored preset and session one level too severe, invisibly, and no version bump helps because `PresetStore` discards on any bump. The combo therefore skips TRACE while the table keeps it, each row carries its `Priority` in item data, and **the combo's order is no longer a `PriorityChoice` index** — `comboPriority()`/`setComboPriority()` are the only bridge. A stored TRACE floor is **not** promoted to DEBUG (that would newly hide every TRACE record); it is applied as "do not narrow by level" by leaving the axis unticked. And the axis ships off because its lowest offered level is now DEBUG: there is no longer a setting that is both ticked and harmless, and the "combo acts on the first click" argument that justified ticking it is covered instead by Qt greying a disabled box's body. `tst_filterpane` pins all three — `theAxesAreInReadingOrder`, `theValueListsTakeTheSpareHeight` (which binds a document, because thread and time are **hidden** without one and a hidden widget is skipped by the layout entirely), `theLevelsOfferedStartAtDebugAndDefaultToInfo` and `aRestoredTraceFloorBecomesAnUntickedAxis`. (d) **The pane has no header row**: the "Filtering"/"No filters" word and the Clear button beside it are gone, `updateSummary()` is now `updateActivity()` and does nothing but `emit activityChanged()`. Its change-guard therefore matters MORE, not less — the label it also protected is gone, so the dock-title write is the only thing left on that path, and that title is a `QTabBar` entry whose rewrite relaid out the tab bar hard enough to starve indexing under a compositor. The **tab marker is now the whole feature** rather than a second copy of it, so `tst_panechrome::theFiltersTabIsMarkedWhileFiltersAreInForce` drives it through a real `MainWindow`; clearing lives only on **View ▸ Clear Filters**, which reaches the same `clearAll()` — and that action's **enablement is asked of `FilterPane::hasActiveFilters()`, the marker's own question**, from the same `activityChanged` signal, so the item and the dot cannot drift and the answer follows the pane's debounce rather than every keystroke. `updateClearFiltersState()` deliberately does **not** consult `activeContext()`: `setActiveView()` calls `updateActionStates()` *before* it rebinds the panes, so an added `hasFile &&` would test the incoming tab's presence against the outgoing tab's filters.

**An empty value list means two OPPOSITE things, and `MatchCriteria::loggerCoversAll` is persisted to tell them apart** (`SPEC.md` §6, `ARCHITECTURE.md` §7.2). The panes are stashed on the way out of a tab and indexing is asynchronous, so opening several logs at once stashed every tab but the last with an enabled Subsystem axis over an **empty** list — nothing had been discovered yet — and hydrating that back as a literal selection left those tabs showing `0 of 1200 records`, permanently: the same pass files every name into `AxisEditor::m_loggerSeen` as shown-and-unticked, which puts the axis beyond the discovery rule's reach for the rest of that binding, and `saveSession()` writes the stash out. The *None* button produces an empty list too and means the exact opposite, so the ambiguity is settled by recording **which** it was, never by reinterpreting the read. Six things are easy to undo. The key is written **only where the name list would be read wrongly** (`coversAll != names.isEmpty()`), and `fromJson` falls an absent key back on that same implication: write it unconditionally and every default state stops serializing byte-identically, and default it to anything else and every seeded highlight rule stored by an older build stops comparing equal to `HighlighterSet::defaults()`, lighting the Highlighters tab's marker on the first launch after upgrade. The three list rules (`AxisEditor::ListRule`) are chosen **per axis from the state, never from which pane hosts the editor** — key the relaxation on the pane and `tst_highlighterpane`'s rule-switching guarantee goes. `Unstated` — covers-all on an axis that is switched **off** — ticks nothing **and un-sees what it leaves unticked**: ticking would materialise a full name list into whichever highlight rule happens to be selected when the pane refreshes, and not un-seeing leaves the Thread axis (which ships off) exactly as broken as before, because `setDocument()` runs its own discovery pass immediately before the pane hydrates and every name is already marked seen by the time `setCriteria()` runs. A **restrictive** selection loads exactly whatever its coverage says, because "these names, whatever turns up later" is the one statement that must not widen. An empty selection stored by a build **before** the key cannot be told from the broken one and is deliberately read as "nothing had been offered" — so a stored *None* from an older build widens once, which is the price of every poisoned tab healing itself. And the regression test must **not pump the event loop between the two opens**: a `QTRY_*` there closes the window the bug lives in, which is exactly why every multi-open case in `tst_multidoc` was green while it shipped.

**A time bound is asked for in whatever terms the timestamp column is showing, and the bound is the INSTANT, never the digits** (`SPEC.md` §6, `ARCHITECTURE.md` §5.1). `AxisEditor` holds two editors per bound — a `QDateTimeEdit` and a `QDoubleSpinBox` of seconds — and shows the pair `Document::timeDisplay()` calls for, in both panes. Three rules are easy to undo. `boundInstant()` reads **`m_renderMode`, not the document's current mode**: `refreshTimeBounds()` runs exactly when the two disagree, so consulting the document there reads seconds as a date at the one moment a bound has to survive intact. `MatchCriteria` keeps storing **display-zone wall clock** — a count of seconds is relative to a baseline belonging to this file, this run partition and this display mode, so it is not portable enough for a preset or a session — which makes the date editors what `criteria()` reads, and means every write to the seconds pair, typed as well as programmatic, must mirror into them or a typed bound silently does nothing. And a `RunSeconds` bound counts from the **selected run**, because the column is per-record and one bound cannot be; `MainWindow::onRunSelected` therefore calls `refreshTimeBounds()` on both panes exactly as a display-mode change does.

**The highlight palette's two theme variants are a nudge, not a flip — the tone belongs to the user, not to the theme** (`SPEC.md` §7, `ARCHITECTURE.md` §8). M5 shipped twelve hues, each deep on a light theme and pastel on a dark one, which meant a theme only ever offered *one* tone and a rule that set a background had nothing readable to put on it: on a dark theme the best of all 144 slot-on-slot pairs measured **1.85:1**, and every background sat between 1.13:1 and 2.09:1 against the theme's own text. It is now three tone bands of eight hues — **Deep, Vivid, Soft** — each closed by a neutral (Ink, Gray, Paper) at `index % 9 == 8`, and a slot keeps its band in both themes. Three things are easy to undo: every slot names the neutral that reads on it (`PaletteSlot::textOn`) and that pairing must clear **4.5:1 in *both* themes**, which is why the answer is one slot index and not a per-theme one; the **Vivid** band must stay out of the dead luminance band ~0.16–0.21 where neither Ink nor Paper reaches 4.5:1, with both variants of a hue on the same side of it (that constraint, not carelessness, is why Vivid Red, Vivid Blue and Gray have near-identical variants); and `HighlighterPane::addRule()` must keep setting the **foreground as well as the background**, because *default* text is now unreadable on half the slots and which half inverts with the theme. `tst_highlight::paletteEveryBackgroundHasReadableText` pins all of it, with the WCAG maths inlined because that test links `loftail_core` only and `UiColors` is UI-side.

**A wrapped record's height is MEASURED, glyph by glyph, and the whole difficulty is that a fixed-pitch font is only fixed-pitch for the characters it actually carries** (`SPEC.md` §5, `ARCHITECTURE.md` §7.1.1). `ceil(chars / cols)` assumes one advance for the whole view, and two kinds of character break that: one the primary face does not carry resolves through a **fallback** face — Han, Kana and Hiragana at 1.662x the Latin advance, Hangul 1.528x, emoji 1.766x — and one whose **ink overhangs its advance** breaks a line a place early, because `QTextLine`'s test allows for the last glyph's right bearing. A CJK log lost a line off **51.7%** of its records and one in seven (size, width) configurations ate a row off the occasional ASCII record ending in `W`, both in total silence, since a wrapped message is deliberately not elided and offers no tooltip (`bugs.md` 21, 22). It is `WrapMetrics` now — a greedy fill over a memoized per-codepoint (advance, ink overhang) pair, **0.34 ms per 4096-record block against the 1.4 ms that block already spends decoding**, where a `QTextLayout` per record is 24 ms and up to 800 ms on payload records. Seven things are easy to undo. `EstimatedGeometry` is keyed on the **wrap width in PIXELS, not a column count**, and `viewportCols()` is gone; `charAdvance()`, `minWrapWidth()` and `kMinWrapCols` stay, because the wrap width's *floor* is still stated in characters and nothing else divides by an advance. A font change must call `m_wrapMetrics.setFont()` **and** `m_estimated.invalidateMeasurements()` **unconditionally**, after the column re-seed: the cache is keyed on a width, and a zoom on a view whose every column was dragged or restored moves no width at all, so `setWrapWidth()` alone answers false and keeps every height the old face measured. A BMP codepoint's overhang comes from **`QFontMetricsF::rightBearing()`, never from the bounding rectangle** — both mean "ink past the advance", but only the first is the number `QTextLine` uses, and the second is the unhinted one, which at 7 pt fits a twentieth `>` onto a line Qt breaks at nineteen. A **zero-advance** codepoint contributes nothing, because a combining mark joins the cluster before it *and* because Qt's unset `glyph_metrics_t` reports x=100000, which would break the line at every mark of a Thai record. A **Common/Inherited-script** codepoint is measured a second time beside a wide base and the wider answer kept: `⚠` is 7.22 px beside Latin and 12 px beside Hangul, because such a character has no font of its own and takes the run's. ASCII is filled **eagerly**, all 128 entries with U+0009 holding the blank the layout substitutes for it, and everything else goes through a **direct-mapped 4096-slot cache** in front of the `QHash` — that one took a pure-Han log from 1.42 to 0.70 ms a block, and without it the walk is all hash lookup. And the memo is per **codepoint**, never per record (invariant #1). What stays wrong is one-sided and stated in `ARCHITECTURE.md`: shaped clusters and `QTextLine`'s absorption of whitespace at a break both give a record a row it does not fill, which loses nothing. **`QFontMetricsF::inFont()` cannot detect any of this** — it resolves through the fallback chain and answers true for U+4E2D and U+1F600 alike — so a screen built on it never fires; that is written down because both bug entries proposed it.

**`QColor::lighter()`/`darker()` are a percentage of the HSV *value*, which means they are no-ops at both ends of the range** — and the log table's zebra band was `base.lighter(108)` for eight milestones, measuring **1.02:1** on a near-black table and exactly **1.00:1** on a white one. It is `UiColors::alternateRowColor()` now, a fixed step from `Base` toward `Text`, near 1.13:1 on both. Three things are easy to undo. It is **not** `QPalette::AlternateBase`, because nothing obliges a theme to make that role differ from `Base` and a theme that leaves them equal takes the band away again in silence — on wrap-always-on, where the band is the only thing marking where one record ends. It is keyed on the **view row, which is a record and not a line** (invariant #2), and `resolveRowColors()`'s caller fills the whole record's rect with the answer, so moving the alternation anywhere near the line loop bands a three-line record in three shades. And it stays in the **`else` of the highlight-rule branch**: tint a rule's background by parity and two adjacent records matching one rule read as two rules. `tst_logview::theAlternatingBandChangesAtRecordsAndNotAtLines` renders the viewport and reads all three off the pixel runs down one column, because none of them is observable any other way; `tst_uicolors` measures the contrast, including that the `lighter(108)` it replaced fails.

**A column that cannot show its value elides, and only a value that is actually cut short offers a tooltip** (`SPEC.md` §5, `ARCHITECTURE.md` §7.1). `HighlighterPane`'s summary column set the precedent — "the column elides; the tooltip does not" — and the log table follows it, cells and header captions alike. Five things are easy to undo. The paint and the tooltip must keep asking `elidedText` of the **same width**, the section's: measure the tooltip against the viewport, or against anything the paint does not clip at, and tooltips start appearing where no ellipsis was drawn and stop appearing where one was. The tooltip is **not** the model's `Qt::ToolTipRole` — the model cannot see a column's width, and `QHeaderView` in particular shows that role unconditionally, which is the "repeats what is already on screen" noise the feature exists to avoid. The **message column is excluded while it wraps** (`estimating()`, or the selected record in `SelectedRecordOnly`) and otherwise answers **per physical line**, because with wrap off each line of a record is clipped on its own; ask about the whole record instead and a one-line message inside a tall record reports itself truncated. The header's tooltip arrives on the **header's own viewport**, which the view event-filters — it never reaches `LogView::viewportEvent()` — and the header's `textElideMode` defaults to `ElideNone`, so the ellipsis there is one line in the constructor and nothing else supplies it. And **`m_header` is now initialized to `nullptr` in the class body and `eventFilter()` guards on it**: `QAbstractScrollArea` installs the view as an event filter on its own scrollbars *from its own constructor*, so `eventFilter()` runs before `LogView`'s body has built the header, and an uninitialized pointer there is a segfault in every test that constructs a view.

**A column's width is SEEDED from the font and never overwrites one the user set.** The per-role pixel table is gone: a width is now `max(header caption, a per-role allowance in CHARACTERS)` measured through the view's own metrics, which is the only unit that means anything before a font is resolved — Priority shipped at 60 px for nine milestones and could not fit the word *Priority*. Five things are easy to undo. The seed runs **exactly twice per view** — the constructor, and `MainWindow::onIndexFinished`, where the intern tables are complete and the Subsystem/Thread columns take the widest name in the file (invariant #4); moving it onto the ingest path makes it an O(intern table) pass per tick, and moving it off `onIndexFinished` costs those two columns the only measurement that is ever exact. `m_userSizedColumns` is what stops a seed fighting the user, and **`restoreColumnState()` marks every column** — session restore builds the views and restores their layouts *before* indexing starts, so without that mark the scan-completion seed silently widens a column narrowed in the last session; the `sectionResized` handler excludes the `0` that a hide/unhide reports, which is not somebody dragging a divider. **`charWidth()` and `textWidth()` floor at 8 px per character**, because a platform with an empty font database (Windows offscreen, which ships no fonts) answers 0 to every advance and an unfloored seed collapses the whole header — every font-derived assertion in `tst_logview` and `tst_multidoc` `QSKIP`s on `QFontDatabase::families().isEmpty()` for the same reason. **"Fit to Contents" is bounded** — the intern table for Subsystem/Thread, the six level words for Priority, and at most 400 sampled records for everything else (the visible ones first, then an even stride) — so the menu item costs the same on a ten-million-record log as on a small one, and a fit **claims its column** exactly as a drag does. And the two header-menu commands are **window-owned `QAction`s with object names** (`fitColumnsAction`, `resetColumnWidthsAction`) acting on the ACTIVE view, following the timestamp submenu: `showColumnMenu` builds its `QMenu` on the stack, so an action created inside it could not be triggered by any test.

**A seeded width is bounded by what is on screen, and by the SUM of the columns rather than per column.** Every term in the seed is measured from the font and the data, which is right for one column and wrong for four: a 40-character subsystem name beside a 40-character thread name comes to some 850 px of Time, Thread, Priority and Subsystem, more than the document area of an ordinary window with a pane docked — so the message column's origin landed at or past the right edge, at the exact moment the scan finished and `onIndexFinished` re-seeded those two columns from the complete intern tables. Nothing rendered wrongly; the message was simply not on screen any more, on a log that had been readable a second earlier, and the collapsed widths were then saved and restored verbatim. `LogView::boundSeedToViewport()` now requires the columns other than the message to fit the viewport less **40 characters of message**, lowering **one cap over all of them at once** until they do — widest first, since a column is only ever over-wide here by asking for a long interned name. Four things are easy to undo. No column goes below `seedFloorOf()`, its caption-and-typical-value width, which is **exactly what it was seeded at before the scan finished**: the bound gives back the growth the intern tables asked for and never a pixel more, so on a window too narrow for even that the layout is the one that was already on screen and the fix cannot make a view worse than it found it. It adds **no fourth caller** — it runs inside `seedColumnWidths()`, and calling it from `resizeEvent` would take a dragged window width as licence to overwrite widths the reader had settled on. A column the user sized is spent from the budget and never reduced, which is what keeps a bound that looks at a sum from fighting a drag — and therefore a session **restored** with the collapsed widths cannot be repaired at seed time at all, since `restoreColumnState()` marks every column as theirs: **Reset Widths is the escape hatch**, and it is one only because it clears those marks and re-seeds *through* the bound, where it used to re-seed to exactly the same collapsed layout. And the bound is inert until `m_viewportLaidOut`, set from `resizeEvent`, because the constructor seeds before anything is laid out and `QWidget`'s default geometry would squash every column on a window with room to spare. `tst_logview` derives its widths from the unbounded seed rather than writing a window size down, and `tst_multidoc::theScanCompletionSeedLeavesTheMessageColumnOnScreen` sizes the real window until the document area is that width and then reads the painted pixels — a document area is worth what the font the *panes* are labelled in leaves of it, which moves independently of the seed.

**The view's line pitch must be the number QT LAYS TEXT OUT AT, and `QFontMetrics::height()` is not it** (`ARCHITECTURE.md` §7.1.1). `QPainter::drawText()` steps a wrapped cell by `QTextLine::height()` — `ceil(ascentF + descentF)` — while `QFontMetrics::height()` rounds the ascent and the descent **separately**, so it comes out a pixel short at 15 of the 27 point sizes the zoom offers. `LogView::lineHeight()` was that for eight milestones and the cost was one pixel of clipped text per line: the bottom of every wrapped record cut off, and past about thirteen lines the last line not drawn at all — silently, because a wrapped message is deliberately not elided and offers no tooltip. It is `qCeil(QFontMetricsF(fontMetrics()).height())` now. Four things are easy to undo. **`measureWrappedLines()` divides a `boundingRect` height, which is in Qt's pitch, by `lineHeight()`** — so the two are one unit or the `SelectedRecordOnly` answer is a line too many and the record wears a blank strip under its own text; fixing either end alone moves the error to the other rather than removing it. **`lineHeight()` is the scroll unit and the hit-test unit too** (`visibleLines()`, `recordAtViewportY()`, `truncatedCellText()`, `digestContentLines()`, `sizeHint()`), so nothing may re-derive a row pitch from `QFontMetrics::height()` locally — they move together or they disagree. `fontMetrics().lineSpacing()` is **not** a fix: leading is 0 for these faces, so it measures identical to `height()` at every size. And the regression test has to run at a size where the two metrics actually **disagree** — the offscreen default is one of the ones where they agree, which is exactly why the suite was green through this — and it has to read the ink back off a rendered viewport, since none of it is observable any other way; `everyWrappedLineOfARecordIsDrawnInsideTheRowItWasGiven` measures the stride between painted lines against the rows they were given, and `aSelectedRecordIsGivenExactlyTheLinesItsWrappedTextTakes` counts them against `selWrapLines()`. `lineHeight()` and `selWrapLines()` are public for that and for nothing else.

**The same rounding one axis over, and SUPERSEDED BY THE PARAGRAPH ABOVE — no height divides by an advance any more, but the rounding rule it records still governs the wrap width's floor: `viewportCols()` divided by a character advance, and every integer advance Qt offers is truncated** (`ARCHITECTURE.md` §7.1.1). *Always On* gives a record `ceil(chars / cols)` rows and then clips its text to them, so `cols` may never exceed what `QTextLine` actually places on a line that wide — and `cols` was `messageWrapWidth() / QFontMetrics::averageCharWidth()`, which answers 7 at the shipped 9 pt where the advance is 7.21875. Below the true advance at the same 15 of 27 point sizes the pitch was short at, so a 379 px column counted 54 characters where 52 fit and the tail of every long record was drawn nowhere — silently, for the same reason as above (`bugs.md` 17). It is `qFloor(messageWrapWidth() / QFontMetricsF(font()).horizontalAdvance('0'))` now. Four things are easy to undo. **`QFontMetrics::horizontalAdvance()` is NOT the fix** — it is a `qRound` and fails at exactly the same sizes — so §7.1's seed helpers `charWidth()`/`charsWidth()` cannot be borrowed here however tempting; only the `F` variants measure what the layout uses. **`qCeil` on the advance is the mirror fault**: it ends the clipping and hangs a blank line off every wrapped record instead (47 columns where 52 fit), so the advance stays fractional and the *division* is what is floored. **`minWrapWidth()` has to move in the same change**, to `qCeil(kMinWrapCols * advance)`, because `viewportCols()` re-raises the count with a `qMax` — leave the floor a truncating multiply and one column of clipping survives the fix at those same 15 sizes. And **exactness at the break was still not bought**, which is what the paragraph above exists for: `QTextLine` allows for the last glyph's right bearing, so a line ending on an overhanging glyph (`W` at most sizes, `x` at 7 pt) broke a character early, which no width-over-advance arithmetic can see — `bugs.md` 22, with the fallback-face version at 21, both since fixed by measuring instead of dividing. `viewportCols()` is gone; `charAdvance()` and `minWrapWidth()` survive as the floor and keep every rule above. Tests sweep the point sizes for one where the metrics diverge (the offscreen default is one of them) and read the record's ink back off a rendered viewport.

**A caption is measured against the rect the STYLE puts it in, and the suite's own style hides it when it is not.** A header section is not its label: `PM_HeaderMargin` is spent either side before the caption starts, 6 px a side on Breeze — the reference KDE desktop's style, which is what the user runs — against 2 on Fusion, which is what an offscreen CI run resolves. So `seedWidthOf()`'s flat `kColumnPadding` left *Priority* opening at 68 px with 56 px of label for a 58 px caption and the header literally painting `Priori…`, at **every** one of the 27 point sizes and after *Fit to Contents* too — the exact failure `SPEC.md` §5 says was fixed, surviving nine milestones because the only style that shows it is the one nothing tests under. Four things are easy to undo. The inset comes from `headerLabelInset()`, which asks the style for `SE_HeaderLabel` exactly as `truncatedHeaderText()` does — one function decides whether a caption fits and the other decides how wide to open the column so that it does, and reimplementing either is how they start disagreeing — over a **synthetic rect of known width**, because the seed runs in the constructor before the header has been laid out and a live section rect there is the default width. It is added to the **caption term only**, in `seedWidthOf()` *and* `contentWidthOf()`: a cell is painted at the raw section rect, so a value owes the margin nothing, and a fix confined to the seed leaves *Fit to Contents* opening any column whose values are shorter than its caption truncated — a `Thread` over a one-thread log, an `Elapsed` or a `Location` over short values. A regression test **passes with the bug in place** unless it does two things — measure the **label rect** rather than `sectionSize`, and install a `QProxyStyle` forcing `PM_HeaderMargin >= 6`, since Breeze is not on the CI runners — and `everyColumnStartsWideEnoughForItsOwnHeading` did neither, which is why it guarded nothing. And a per-role allowance is measured as **one string**, `charsWidth(n)` = `textWidth(QString(n, '0'))`, never `n * charWidth()`: a `QFontMetrics` advance is an integer, and 23 characters of that rounding came to a whole character in both directions — at 29 pt the Time column opened one pixel narrower than the very timestamp its allowance names, which is a seed eliding the value it was seeded for.

**The mirror of that trap, one metric over: a test that pins a PAIR when the claim is about one member of it, and a test that hard-codes a geometry threshold.** `PM_HeaderMargin` above is the case where the style the user runs is harsher than the style CI resolves; these two are the case where the numbers simply differ and the test happened to be written under one of them. **`PM_ScrollBarExtent` is 14 under Fusion and 21 under Breeze; `PM_DefaultFrameWidth` is 1 under Fusion and 0 under Breeze** — so any test that measures a viewport, an inset or a remaining width against a written-down number, or against a *sibling* widget whose scrollbar state may differ, is green by luck. Two shipped that way. `tst_highlighterpane::theAxesSitWhereTheFiltersPanesDo` compared the `{left, right}` inset **pair** of an axis group box across the Highlighters and Filters panes, when the claim (commit 3e91d0c) is only about the **left** indent — `AxisEditor` supplies its own `kSideMargin` and a pane layout margin is *added* to it. The right inset came along because the helper returned a pair and the two numbers happened to be symmetric at 460×820 under Fusion. They are symmetric only while neither pane's axis scroll area needs a vertical bar, and the Highlighters pane spends ~240 px above the editor on the rule table and its button row, so it scrolls where the Filters pane does not: it fails at any pane height in the ~672–786 px band **under Fusion too** (at 700 px: 6/20 against 6/6), and under Breeze up to 916 px, because Breeze's taller group-box frames push `AxisEditor::minimumSizeHint().height()` from 551 to 672. The passing case cleared by 34 px. It now compares left insets across the panes and checks the right one **per pane** against that pane's own bar (`right == left + (bar visible ? bar width : 0)`, verified against every measured combination), and runs at two heights so the scrolling case is exercised under the default style. `tst_logview::theSeedKeepsTheMessageColumnOnScreenWhereTheNamesAreLong` resized the **widget** to a measured width and then asserted the *viewport* was narrower — true only because Fusion's frame steals a pixel a side, so under Breeze the guard fired "nothing is being tested". `layOutAt()` now takes a **viewport** width and adds `2 * frameWidth()` itself, which is the general rule: ask for the quantity the code under test is bounded by, never for a widget size plus an assumption about the chrome. Neither is a production defect — the panes are tabbed into one dock and never on screen together, and nothing promises the two give the axes the same content width. Reproduce with `QT_STYLE_OVERRIDE=Breeze ctest --test-dir build`, which is as cheap as the empty-`FONTCONFIG_FILE` run below and catches a different class of thing; do **not** answer either by forcing `ScrollBarAlwaysOn` (which spends 14–21 px of dock width for ever and hangs a dead bar on the Filters pane) or by making the test's pane taller (916 px passes Breeze today and is one Qt, style or font bump from failing again, exactly as 820 was).

**A zoom that makes the line space SMALLER used to throw a detached reader to the end of the log**, and it is the same trap `endFilterUpdate()` records one level up. `applyFontChange()` re-seeds the columns, re-measures the estimator and recomputes the geometry — and under `AlwaysOn` a smaller font fits more characters across the message column, so the estimated line space **contracts** and Qt clamps the old scroll value into the narrower range. A clamp landing at the bottom reaches `updateFollowFromScrollPosition()` as an ordinary scroll, so the view starts following again and the function's own `if (m_following)` branch then sends it to the tail instead of anchoring. `m_inFollowScroll` is therefore held across the **whole** invalidation and not merely across the re-anchor's own `setValue` — still a flag and never a `QSignalBlocker`, for the queued-`rangeChanged` reason — which also makes `m_following` at the branch mean what it meant before anything moved. It was invisible until the column widths above changed the wrapped column count, which is the shape of it: nothing about the bug is in the zoom path, and the zoom path is where it fires.

**Log text zooms, and the stale estimator is the trap it exists to record** (`SPEC.md` §5, `ARCHITECTURE.md` §7.1.5). `Ctrl +` / `Ctrl -` / `Ctrl 0` and `Ctrl`+wheel move ONE application-wide point size, held in `Fonts.h` — not per view (invariant #7's list is what differs between two views of one log, and a reader's eyesight does not), not in `LogProfile` (that says how a log is *read*), and not in the session (which describes one window's tabs, where two windows would disagree): plain `QSettings`, written the moment it changes. Only the SIZE moves; the family stays the platform's fixed-pitch face, because §7.1.1's height model memoizes one metric per codepoint and a proportional face is what makes that memo unbounded. `MainWindow::setLogFontSize()` is the single funnel and re-fonts every open view, **digest strips included**. Five things are easy to undo. The view notices through **`QEvent::FontChange` and nothing else**, so it does not matter who set the font — and `applyFontChange()` must **guard on `m_header`**, because the constructor sets the font before it builds the header, the same trap `m_header`'s `nullptr` initializer records for `eventFilter()`. **Dropping the estimator's measurements is the invalidation nothing else performs**: `ensureEstimatorBound()` rebinds on the index's ADDRESS and folds in what its tail has grown, and a font change moves neither, so without it the estimator reports wrapped heights measured at the old face for the rest of the session — and it must run AFTER the re-seed, which moves the message column's origin and therefore the width itself. It is now `m_wrapMetrics.setFont()` plus an **unconditional** `m_estimated.invalidateMeasurements()`, for the reason the wrap-metrics paragraph above gives: the cache is keyed on a pixel width, which a zoom need not move. The re-anchor is the **top RECORD, via `applyDebouncedResize()`'s precedent and NOT the filter bracket** — that bracket speaks in source ordinals because a refilter replaces the record space, and a font change replaces nothing — with `m_inFollowScroll` as a flag, never a `QSignalBlocker`. `seedColumnWidths()` gains a **third** caller here (constructor, `onIndexFinished`, font change) and `m_userSizedColumns` is what keeps a dragged width where it was put. And **`Ctrl`+wheel is reported, never acted on** (`zoomStepRequested`), because a view that re-fonted itself would leave every other view behind; the wheel remainder accumulates, or a trackpad's stream of small deltas means something different from a mouse notch.

**A measured block is measured only up to a RECORD COUNT, because the index under it is live** (`ARCHITECTURE.md` §7.1.1). Under wrap Always On, `ensureEstimatorBound()` rebound on the index's address and its **block count** — which moves once every 4096 records — so up to 4095 appends into the partly-filled last block changed nothing, and `EstimatedGeometry::recordHeightLines()` read a per-record height vector one entry short per appended record: a `QList::at` abort in a debug build, an unchecked read into allocation slack in a release one. A trailing record growing continuation lines in place moved neither count, so it kept its stale height and the scroll range never grew to reach its new lines. Three things are easy to undo. `syncTail()` compares **both** the record count and the trailing record's display-line count, because a live log grows in two ways and only one of them moves the count. A block is now measurable **in part** — `syncTail()` truncates the trailing block's cache back to the OLD trailing record (the first that can have moved, invariant #9) instead of dropping it, `isBlockMeasured()` means "the cached prefix covers the whole block", and `LogView::measureBlock()` starts at `measuredRecordsInBlock()`; drop the block instead and a tailed log re-decodes 4096 messages **on every paint**. And the three mapping functions **bounds-check the cached prefix rather than trusting it**, and reach it through `constFind` — `QHash::operator[]`'s const overload returns the vector **by value**, on a path walked once per painted record.

**Everything that moves the message column's ORIGIN has to re-measure, and `sectionMoved` is not a no-op outside Always On** (`SPEC.md` §5, `ARCHITECTURE.md` §7.1.1). Under Line Wrap ▸ Always On a record is given `ceil(chars / cols)` rows and `cols` is counted from `sectionViewportPosition(msgCol)` to the viewport's right edge — so a column **resize**, a column **move** across the message column and a **horizontal scroll** all change it, and for nine milestones only the resize said so. `sectionMoved` did `viewport()->update()`, `scrollContentsBy()` set the header offset and repainted, and both left every row on screen measured against the old width: a blank band under every record where the wrap area grew, and the tail of every message clipped away where it shrank (`bugs.md` 9, whose own rationale got this next part wrong). All three now call `recomputeGeometry()` — one funnel, and in Always On it restarts the 120 ms debounce so a dragged bar remeasures when it settles rather than per pixel, with `applyDebouncedResize()` re-anchoring on the top record. Three things are easy to undo. A move does **real work in `SelectedRecordOnly`**, where it re-measures `m_selWrapCache` at the new origin, so a call scoped with `if (estimating())` would leave the selected record banded to a height its text no longer takes — it is two modes fixed, not one. The `sectionMoved` lambda must **not** `markUserSized()`, which is `sectionResized`'s alone: moving a column is not sizing it, and marking it there freezes the font seed out of a column nobody dragged. And the scroll call sits inside `dx != 0`: a vertical scroll moves no origin, and re-measuring on one puts a text-shaping pass on the wheel. The three regression cases render the viewport and read the ink back, because that is the only place any of it shows — every widget holds the right value throughout, and what is wrong is the number of rows the record was drawn into.

**One expression computes the wrap width, and its floor is in CHARACTERS** (`SPEC.md` §5, `ARCHITECTURE.md` §7.1.1). `LogView::messageWrapWidth()` is the message column's origin to the viewport's right edge, floored at `kMinWrapCols` (20) characters, and all four users take it from there: `EstimatedGeometry` is keyed on it and `WrapMetrics` fills records at it, `recomputeGeometry()` measures `m_selWrapCache` in it, and both wrapped paint sites lay the cell out in it. They used to compute it four times over with four different floors — 1 px, 50 px, 10 px, 10 px — which was two bugs at once. At 1 px the estimated count had no bound below: a message origin pushed to or past the right edge wrapped every record at one character per line, every record measured `kDisplayLineCap`, and one 1400 px record filled a 466 px viewport at both ends of the file (`bugs.md` 11). It is not a corner: the columns before the message are seeded from the intern tables **when the scan finishes**, so a long logger name and a long thread name collapse a view that rendered normally while it was indexing. The 50-against-10 half was the same defect under `SelectedRecordOnly` and invisible in pixels — the paint wrapped narrower than the measure and `drawWrappedCell()` dropped the rows it had not been given, cutting a record off mid-word with no ellipsis and no tooltip. Four things are easy to undo. A **fifth site that recomputes the quantity** puts the bug straight back, in whichever direction it rounds. The floor must stay **in characters**, because log text zooms across 27 point sizes, and **at or below ~25 columns**, which is as low as `tst_logview`'s `aimWrapWidth()` aims while asserting a record wraps deep — a higher floor defeats seven cases silently instead of failing them. Only the **width** is clamped and never the origin: putting the cell back inside the viewport is `bugs.md` 18's open product question, not this one's. And the scroll range is **`qBound`ed into `int`**, not cast — at 100 lines a record the `qint64` total overflows at 21 million records and a negative range is one `QAbstractSlider` collapses to zero, i.e. a log that cannot be scrolled at all. `tst_logview` pins the floor three ways, since no one of them sees the whole of it: the estimated heights and the scroll total at an origin 40 px inside, on and 60 px past the right edge; the record bands read off the rendered pixels at the origin past it, where the message is drawn wholly off-screen and the bands are all there is; and the selected record's cell rendered in two views at once, where the narrow one's visible strip must be pixel-identical to a reference laid out at the floor's own width — which is the only way to see that the paint used the width the measure did.

**A wrapped message is entitled to the space after its column only while there is nothing after it** (`SPEC.md` §5, `ARCHITECTURE.md` §7.1.1). `messageWrapWidth()` is still the ONE expression every wrap width comes from — the estimator's key, `recomputeGeometry()`'s `m_selWrapCache` and both paint sites read it — but it answers `viewport()->width() - x` only while `messageIsLastVisibleColumn()`, and `qMax(minWrapWidth(), sectionSize(msgCol))` otherwise. The columns are painted in visual order with no fill of their own, so a message laid out to the right edge regardless was drawn *under* every field after it on the record's first line — two strings of glyphs in the same colour on the same pixels, and it took no gesture to reach: `%d{…} [%t] %-5p %m (%c)%n` is an ordinary pattern and puts the subsystem after the message (`bugs.md` 18). Five things are easy to undo. **The last-column branch is byte-for-byte what shipped**, which is what keeps this decision independent of `bugs.md` 19 — that collapse happens in natural order, and a formulation without the special case would leave a message column seeded past the right edge with no visible cell at all instead of one reached by scrolling. **"Last" is walked back from the end of the VISUAL order past hidden sections**, never compared against `count() - 1`: the columns are movable and any of them may be switched off. **The paint CLIPS at the section and does not lay the text out narrower** — the width is floored at `kMinWrapCols` characters, so a section under the floor is measured wider than it may be drawn, and re-laying it out at the section would break its lines somewhere the height was not counted for, which is the measure-against-paint mismatch this seam exists to prevent. What the clip costs is the tail of each line on a message column both narrow and not last, with no ellipsis and no tooltip and nothing to scroll sideways to — `SPEC.md` §5 says so rather than leaving it to be discovered. And **`estimating()` and the exact path both ask `wrappedMessageColumn()`, which is -1 for a HIDDEN message column** as well as for a format with no `%m`: without that, hiding the column from the header menu left every record wearing the wrapped height its invisible message wanted and the paint skipped the section, so a log rendered as one line of fields and three blank rows per record with the scrollbar spanning them. `columnIsOnScreen()` reads the section's WIDTH and not `isSectionHidden()` alone, because `QHeaderView` resizes a section to 0 *before* it marks it hidden and the `sectionResized` that reaches `recomputeGeometry()` is emitted from inside that resize — the flag is still false at the one moment the geometry has to change. It is all observable only in pixels: `tst_logview` renders two views of identical geometry, one with a long message and one with two characters, and counts the pixels that differ outside the message column.

**`Alt+Z` toggles wrap Off ↔ Always On by TRIGGERING the existing mode actions.** There is one path that sets wrap, and it is the one that also writes the choice into the log's settings node (M20) — which is why the exclusive checkmark follows with nothing extra wired up. Two-way, not a three-way cycle: *Selected record only* is picked for one record, and stopping there on the way would make the key's effect depend on invisible state and re-lay out the whole view on the way past. The three mode actions now carry object names (`wrapOffAction`, `wrapSelectedAction`, `wrapAlwaysOnAction`) so a test never finds them by their visible text.

**A selection is built with the POINTER now, and all three gestures extend from one anchor** (`SPEC.md` §5, `ARCHITECTURE.md` §7.1). Press-and-drag extends a range as the pointer moves, a drag held past an edge autoscrolls and goes on extending, Ctrl+click takes one record in or out without clearing the rest, and Shift+click is untouched — because a drag step *is* the Shift path, `setCurrentRecord(record, true)` off `m_anchor`, reached from a mouse move instead of a key. Four things are easy to undo. **`mousePressEvent()` takes the LEFT button only**: on X11 a right press arrives *before* the `QContextMenu` event, so a press that moved the selection collapsed a multi-record one before the menu (§7.4) could decide to leave it alone — the case "the menu acts on the selection" exists for, and invisible for as long as such a selection took a Shift+click to build. **A Ctrl press deliberately arms no drag**, because an additive drag would have to snapshot the whole selection to put back the rows the pointer passed over and came back from, and toggling as it went would make the result depend on the path rather than on its two ends. The **autoscroll timer scrolls through `verticalScrollBar()->setValue()`, never `scrollContentsBy()`** — this *is* the user scrolling, so follow must detach exactly as it does on a bar drag — and it is stopped by the release, by `hideEvent()` (a tab switched away mid-drag never sees a release) and by `handleModelReset()`, which drops `m_anchor` on the very next line and would otherwise leave a drag extending from nothing. And the tests drive real `QMouseEvent`s at the **viewport**, because the gesture is the whole of what was added and every case passes against the handlers called directly; a move sent *after* the release has to be built by hand, since `QTest::mouseMove` sends no event at all once the buttons are up.

**`HighlighterPane::m_updating` must be SAVED and RESTORED, never forced false on the way out.** `loadEditorFor()` is called re-entrantly by `reloadRuleList()` without either function saying so — `m_ruleList->clear()` drops the current row, which emits `currentRowChanged(-1)` — so ending `loadEditorFor()` with `m_updating = false` unguarded the *rest* of the rebuild. The loop's `setFlags` then fired `itemChanged` before `setCheckState` had run, the handler read the not-yet-set check state as `Unchecked` and wrote `enabled = false` back into `m_rules` **through the very reference the next line reads** (`for (const HighlightRule &r : m_rules)`), so `setCheckState` was handed the false it had just caused. Every rule switched itself off and all highlighting vanished, from the **second** rule onward only — `clear()` on an empty list emits nothing, so one rule always looked fine. Found by driving the real record menu, not by any test; `tst_highlighterpane::reloadingTheListKeepsRulesEnabled` now pins it, including that a rule the user turned off stays off across a rebuild.

**Every user-facing string goes through `tr()`; loftail ships no translation and is English-only** (`ARCHITECTURE.md` §9.1). The split is the part that is easy to get wrong, and getting it wrong is silent both ways: **translate** prose — labels, menu items, tooltips, window titles, status text, error messages, `--help`. **Never translate** `setObjectName` (the test contract, and dock names that `restoreState()` keys off — translating one breaks saved layouts on upgrade), JSON and `QSettings` keys, regex fragments, log4cplus conversion patterns, Qt date codes, `priorityName()` (it must round-trip against log text, invariant #4), `SshExecCommands`' shell text, the `ssh` scheme, and the name "loftail". Nothing in `src/core` is a `QObject`, so a core file carries a one-line `Q_DECLARE_TR_FUNCTIONS` shim named for its type rather than a hand-rolled `tr()`, which `lupdate` would not understand. Check the result with `cmake --build build --target loftail_lupdate` and read the generated `translations/loftail_en.ts` — an object name or a regex in there is the bug.

**Never identify a widget by its visible text.** `SshPromptDialogs` distinguished two same-role buttons with `text().contains("Remaining")`, which the first translated build would have turned into a silent behaviour change in the bulk-restore path. Object names and pointers, in `src/` and in `tests/` alike; `tst_remoteopen` found the Save button by label, and it stopped working the moment the button learned to say "Update".

**`src/core` contains no `QMutex`, `QMutexLocker` or `QWaitCondition`, and must not regain any** (`ARCHITECTURE.md` §13.1). Qt's TSan annotations live in `qmutex.h` and are compiled into loftail's translation units, but the system `libQt6Core` is not built under TSan — so `QWaitCondition::wait()` unlocks and relocks *inside that library*, unannotated, and TSan's happens-before chain breaks at every wait. Correctly guarded data then reads as a race with both accesses reporting the same held mutex. Measured on one stress harness against **known-good** code: 37 reports with `QMutex`+`QWaitCondition`, **0** with `std::mutex`+`std::condition_variable`, and the 37 were loudest about the file that had just been fixed. The ban stops at `src/core`; `src/ui` and test scaffolding may use Qt's primitives, and a plain `QMutex` with no condition variable is fine anywhere because it annotates symmetrically. The same trap catches `QThread::wait()`, which joins through a `QWaitCondition`: a test whose own load generator needs joining uses `std::thread` (`tst_gatestress`, `tst_archivemembers`).

**ASan is a CI gate; TSan is not, and the reason is the sanitizer runtime rather than loftail.** The `sanitizers` job builds `-DLOFTAIL_SANITIZE=address` and runs all 56 tests with leak detection and `detect_stack_use_after_return` on, clean. **Nothing of loftail's is suppressed:** the one by-design retention, an abandoned fetcher whose thread is still running, is parked in a reachable static instead of leaked precisely so that it needs no entry (`SourceSpool::drainRetired`). `tests/lsan.supp` holds exactly one third-party entry — libproxy, which Qt dlopens from `QTcpSocket::connectToHost` for a system-proxy lookup and which never frees its GObject manager. It shows up on the ubuntu-24.04 runner and not on a 26.04 box with a newer libproxy, and only when the background reconnect gets as far as a socket, so it is suppressed by name rather than left to be rediscovered as a flaky red build. TSan is a supported build with `tests/tsan.supp` and a `threading` CTest label, and reaches zero reports on the tests it completes — but its own thread registry aborts inside `pthread_create` from `QThread::start` on a recycled `pthread_t`, killing 6 of the 17 labelled tests, identically under GCC 15 and clang 21, and predating this work. Run it by hand; do not wire it into CI expecting green.

**Neither sanitizer found the M17 call-gate bug that prompted them, and that is the lesson.** Sixty twelve-way-parallel ASan runs against the pre-fix tree reproduced nothing — the slowdown closes the 1-in-28 window — and TSan never flagged the unlocked `abandoned` read, because no test went near the state that mattered. Sanitizers amplify coverage; they do not create it. `tst_gatestress` is what actually pins it: it drives a cancel raised *from inside the work*, through a nested event loop, which is the only shape in which rule 2 has anything to say — a cancel posted from a timer can never land while `drain()` is running, since both are the application thread. It fails five times out of five against the pre-fix gate with no sanitizer at all.

**M18 complete, and SUPERSEDED BY M20** (below): a file loftail had not seen before was tried against a format the user chose rather than a constant, held in Edit ▸ Preferences and promotable from the Log Format dialog. Its store, its dialog and its "also use this format for new files" checkbox are all gone; what survives is the shape of the argument — the default goes through `offerFormat()` like anything else, and `contains("pattern")` beats `isEmpty()`. Both rules are restated for the tree in the M20 paragraph. **`DefaultFormatStore`'s three-of-seven-fields rule is the one thing that did NOT survive**, deliberately: under whole-node values a node holds everything or nothing, and the per-level exception it created is exactly the complexity M20 exists to remove. The caution it embodied lives on in the migration, which takes the old default's three fields and leaves the rest at their built-in values.

**M20 complete: a log's settings come from the most specific of THREE levels, and the middle one is new** (`SPEC.md` §4, `ARCHITECTURE.md` §8). Defaults, an ordered list of **file patterns**, and per-log entries — one JSON file, `logsettings.json`, resolved on every open and edited as a tree in File ▸ Preferences. The two stores it replaces had no room for "every `*.audit.log` is written like this", so a house layout shared by a hundred files was confirmed a hundred times. **File ▸ Log Format… is gone** and `LogFormatDialog` with it; Preferences is the one way in, which makes the promotion that dialog's checkbox performed a thing the user can see and undo. Each level holds a complete `LogProfile` — the seven `FormatSettings` fields plus the wrap mode a new view starts in — and the deepest match supplies **all** of them; the levels are never merged field by field.

**Eight M20 rules that are easy to undo by accident.** `LogSettingsTree::setFileProfile()` **erases** a per-log node whose profile equals what its address inherits, and it is the single funnel every write goes through — the format dialog, the timestamp header menu, the Run pane, the wrap menu. Break that and merely *opening* a log leaves an entry behind for ever, "Promote to Parent Pattern" stops being self-cleaning, and every resume of a remote log rewrites the whole file. **Its other half is `pruneRedundantFiles()`**, run from `PreferencesDialog::rebuildTree()` and once more from `accept()` (which follows a `commitCurrent()` no rebuild has seen): `setFileProfile()` re-tests only the node it is *writing*, and a node stops saying anything of its own just as surely when the pattern above it is edited — which nothing writes. Its `except` argument spares **the node of the log that is open** (`m_currentAddress`), which says nothing new by construction while it is the scratch node `selectLog()` just created, so an unexempted sweep deletes it between its creation and its first keystroke; `accept()` passes no exception, which is what still prunes it if the user left it that way. The store keeps loading with `insertFileProfile()` and must go on doing so — a load is not a gesture the user can watch. A per-log node stores **no parent link**; the parent is derived by running the matcher, which is what makes deleting, editing or reordering a pattern re-home its logs with nothing to go stale — add a stored `parent` and every one of those operations needs fixing up. The **virtual "no matching pattern" parent is gone** — see the paragraph below on the file level listing one row — and the absence of a match is now a row's position, directly under the defaults, rather than a widget-only parent standing in for it; the objection it used to answer (a row that is not a row, the same one the pathless default drew in the old cache) is answered by there being nothing at all. The **wildcard converter is hand-written**: `QRegularExpression::wildcardToRegularExpression()` globs paths and its opt-out, `NonPathWildcardConversion`, is **Qt 6.6** — above the 6.4 floor, where the dev machine's 6.10 proves nothing. `LogSettingsStore::migrateLegacy()` runs in the `MainWindow` constructor **before `restoreSession()`**, because restore now resolves through the tree rather than carrying each document's format; backwards, and every restored tab opens on the built-in defaults once, invisibly, on the first launch after upgrade. `openFile()`'s prompt gate is **gone entirely** — it was `!cached && pattern.isEmpty()`, then `pattern.isEmpty()`, and is now no gate at all, because every level is checked against the file including a `--pattern` (see the paragraph below). **The dialog applies nothing**, including "Apply to current file", which only records the request: applying reindexes and destroys the very `Document` the dialog is previewing, and it is also what makes Cancel discard a pattern added, a node deleted and the node created for the log in one gesture. That button no longer calls `accept()` — it **arms** a request that OK carries out, so it stopped being the one control on a panel of in-place edits whose press ended the session — which costs three things: it is **checkable** and down only on the node the request names (`m_applyNode == currentRef()`, so a press elsewhere arms that node and a second press on the same one withdraws), it carries a **notice** saying which log is re-read and when, because a press that leaves no mark is worse than one that closes the dialog, and it stores a **`NodeRef` rather than a profile**, which `accept()` re-reads *before* the prune — a snapshot would apply the settings as they were before the editing the deferral exists to allow. And `LogProfileEditor::profile()` writes its own fields **over** `FormatEditor::settings()`, never before — that function builds a fresh struct, and its stash of `timeDisplay` and the `runStart*` triple is still what keeps a choice made elsewhere alive through a pattern edit.

**`--pattern` WINS over the settings tree and is not BELIEVED by it, and the flag that used to say otherwise no longer exists.** `openFile()` overrides the resolved pattern with the switch's, exactly as before, and then `openWithSettings()` judges it against the log like every other level (`SPEC.md` §3, `ARCHITECTURE.md` §8): it fits, so it is persisted through `setFileProfile()` — which erases the node if that is what the log inherited anyway, the redundancy rule applying to the command line like everything else; or it does not, so Preferences opens on the log's node, and `FormatOutcome::Declined` already means "abort the open", which is the whole of "the file is not opened and `--pattern` is not saved anywhere". Nothing new was added for any of that. **What was removed is `openWithSettings()`'s `promptIfNoMatch` PARAMETER**, whose one caller passed `pattern.isEmpty()`: that spelling silently controlled three things at once — the modal `offerFormat()`, `persist`, and the deferred `pendingFormatPrompt` a waiting or empty log is owed — so a supplied pattern skipped the check *and* was written under the log's own key **unchecked**. One mistyped switch therefore replaced a working remembered format with an unparseable one, after which every ordinary launch with no switch at all raised the format dialog; where the switch happened to equal the defaults, the redundancy rule *deleted* the log's entry instead. It is a local initialised to `true` now, and the only thing that may still turn it off is `nothingToJudgeYet` — a log with no bytes, whose prompt is deferred to the first resume that has some. Two consequences to keep straight rather than fix: an **unattended launch** whose pattern does not fit now blocks on a modal dialog and opens nothing, which is the product ruling and not an oversight (a wall of plain text that also overwrites the settings is not a better answer for a script); and an **explicitly empty value** — `--pattern "$FMT"` with `FMT` unset — names no format, so it is the bare launch and each log's own settings stand, deliberately not an error. `tst_openflow`'s six `…SuppliedPattern…` cases pin every branch, and `tst_remoteopen::aBackgroundResumeRaisesNoFormatDialog` had to stop arranging its background tab by passing a pattern, which is how it silently switched the prompt off.

**The Preferences splitter opens at a width measured from the tree's own rows, and is settled exactly once.** A fraction of the dialog knows nothing about the labels — at the 1:2 stretch it shipped with, the virtual "Logs with no matching pattern" row was elided on a window with room to spare, and at any font larger than the developer's it stayed elided. That row is gone, so the regression test supplies a long **pattern** instead, and widens the dialog first: the 220 px floor and the 40% cap are close enough together that a label clearing the floor at one font size is into the cap at the next, and the case would then be failing on the cap, which is a different test's subject. Three traps: `applyInitialSplit()` runs from `showEvent()` and **must `layout()->activate()` first**, because the show event beats the posted layout request and a split computed against a zero-width splitter is redistributed from nothing by the stretch factors; it is guarded by `m_splitSettled`, which `splitterMoved` also sets, because a width recomputed on every `rebuildTree()` takes the handle back off the user the next time they add a pattern; and the width is **capped at 40% of the splitter**, because a pattern is a line the user types and a long one would otherwise squeeze the settings the tree exists to reach. Every tree row carries a tooltip for the same reason the cap exists — the pane can be narrower than a label, and the widget's own elision is only acceptable while the rest is one hover away. `tst_preferences` measures the rows at **two font sizes**: the offscreen default alone passes with the bug in place.

**M19 complete: a highlight rule's effect is a SET of actions, and colour is one of them** (`SPEC.md` §7, `ARCHITECTURE.md` §7.5). Four ship — colour, digest, mark tab, notify — each opt-in per rule, so a rule may match and not colour, and a rule carrying nothing is parked rather than deleted. First-match-wins becomes **per action**, so adding a rule for one effect can never silently switch off another rule's. `ideas.md` #12–14, all three, with the product ruling on 13/14 going the other way from what that note predicted.

**§11 still says loftail does not do alerting, and the desktop notification contradicts it.** That is the user's explicit ruling, taken twice: ship all three, leave §11 **byte-identical**. The contradiction is recorded in the M19 commit message and in `PLAN.md` M19 — do not "fix" the spec by editing §11, and do not remove the notification to make it true.

**Most of M19 is one seam.** `LogModel` read *the* document's `FilteredIndex` in four places and `LogView` in three; all seven now go through `LogModel::setViewIndex()`/`viewGeometry()`/`sourceRow()`, so the digest strip is `new LogView(doc, digestModel)` over a second `FilteredIndex` — the M15 lever one level up. Plus `setHighlightAction()`, which is what makes a digest row wear the colours of the rule that put it there whether or not that rule also colours the log. **The defaults reproduce the old behaviour exactly, and `tst_logmodel`, `tst_logview`, `tst_filtercontext` and `tst_tail` passing UNALTERED is the proof** — if a change to them becomes necessary, the seam has stopped being inert.

**The digest strip is CAPTIONED and its rows are CHRONOLOGICAL, and both are load-bearing.** A second table under the first, holding copies of rows in the log above it, reads as a rendering fault until it is named, so a body-less `SectionBox` says "Digest" over it — a **sibling**, never a parent, because `LogView::digestContentLines()` caps the strip at a third of `parentWidget()`'s height and a box sized from the strip's own size hint would cap it against itself. And `publishDigest()` dedupes by ordinal (which `std::unique` requires) and *then* reorders by timestamp: it is the one place records from different points in the file are stacked, and log4cplus appends in the order threads reach the appender rather than the order they stamped. A record with no timestamp keeps its slot and never reaches the comparator — `kNoTimestamp` is `qint64`'s minimum, so sorting on it pins unparsed lines to the top, and the "unorderable, return false" comparator is not a strict weak ordering, which is UB in `std::stable_sort` rather than an odd order.

**Six M19 rules that are easy to undo by accident.** `HighlightRule::fromJson` tests **`contains("actions")`, never the array's emptiness** — an empty array means "matches and does nothing", which is one click away from unticking Colour, and reading it as "nothing saved" silently re-colours every parked rule on the next launch (the trap the settings tree's `contains("pattern")` records for an empty saved pattern). `toJson` **omits the key for a colour-only rule**, so everything written before M19 serializes byte-identically and neither store's version moves — and it must not move: `PresetStore` gates on exact equality with no migration (a bump discards every preset), while `SessionStore` does migrate v1/v2 upward but a bumped file is unreadable by any shipped binary. The tab marker is set **above** the `ingested` handler's `ctx != activeContext()` early return, because a background tab is the only case it exists for; below it, the feature works perfectly with one tab open and never fires in real use. The digest **republishes when the provisional record changed even if the ordinal list did not** — `FilteredIndex` holds a 32-byte *copy*, so a digest row that grew a continuation line renders at a stale height for the rest of the session (`publishDigest(force)`). The digest index is **always active, never `clear()`ed**, because an inactive `FilteredIndex` is the *identity* view and the strip's visibility reads its model's `rowCount()` — clearing an empty digest puts the whole log in the strip under the log. And `LogView::sizeHint()` **must stay a pure query**: `setVerticalScrollBarPolicy()` calls `layoutChildren()` whether or not the policy moved, and layout asks the hint, so setting it from inside the hint is unbounded recursion — it hung `tst_multidoc`. `refreshDigestCap()` is the mutating half, driven from `DocumentView::resizeEvent` because the cap is a fraction of the *parent's* height.

**A `DocumentView` now holds TWO `LogView`s, so `findChildren<LogView *>()` no longer counts views.** Every counting or lookup site across `tests/` names the one it means — `findChildren<LogView *>("logView")` — with one deliberate exception in `tst_multidoc`, where the claim is that a dock holds no log view *of any kind*. This is the case that cashed in "object names are the test contract precisely because they are not the visible text".

**M19's notification has no honest CI coverage, and nothing can give it any** — the runners are headless with no tray and no notification server, so `QSystemTrayIcon::isSystemTrayAvailable()` is false and `showMessage()` is unreachable. `showMessage()` is also a silent no-op on a *hidden* icon, so "notify" necessarily means loftail puts an icon in the user's tray; it is created on the first rule that asks and destroyed when none does. `isSystemTrayAvailable()` being false is the **ordinary** answer on a stock GNOME/Wayland session — the reference desktop — so the degrade path (pane disables the control and says why; a Notify rule behaves as if it carried Tab) is the common path there, not a corner. What *is* ungated is everything the delivery is decided by: `tst_alertpolicy` drives the rate limit directly with an injected clock, and `tst_highlighterpane` drives the degrade branch.

**A rule's four actions now live in the rule LIST, which is therefore a `QTableWidget`** (`SPEC.md` §7, `ARCHITECTURE.md` §7.5). Six columns and **no header row** — tick, what it matches, both colour pickers in one cell, then a checkable icon button per action — so every rule's whole effect is on screen at once and settable without selecting that rule first, and the `Action` and `Condition` captions are both gone: what is under the table is an `AxisEditor` and nothing else. The header went because a legend earns its row only while the cells cannot speak for themselves: an action button wears its own glyph in every row, and a picker says which role it sets by the bar under the text picker's letter. The three actions are `QToolButton`s and the rule's own tick deliberately is **not**: it says whether the rule runs at all, and a fourth pressed-in button beside three of them would read as a fourth action. Five things are easy to undo. **`HighlightAction::Color` is derived from the two swatches** (`applyColourAction`) and has no tick of its own, so it cannot drift from them; it is re-derived on ingest as well as on edit (`normaliseRules`, from `setDocument` and `restoreState`), because a rule arriving from a session or preset claiming to colour while naming no colour would be drawn as two empty swatches while silently winning the `Color` action, first-match-wins being per action. **Each row owns its two pickers and each picker carries its row in a `"ruleRow"` property**, so every reorder goes through `reloadRuleTable()` and that rebuild starts with `setRowCount(0)`, never `clearContents()` — a surviving cell widget with a stale row index writes the next edit into a different rule. **`m_updating` is still saved and restored, never forced false**: the rebuild drops the current cell, which re-enters `loadEditorFor()`, and the builder's own `setCheckState` calls are otherwise read back as user edits — the exact shape of the M19 bug that switched every rule off from the second one on. **The enable column is a delegate** (`CheckCellDelegate`), because Qt lays a view item out from the left edge and ignores the item's alignment, and the default hit area is the 13 px indicator alone; **every column but the summary is `QHeaderView::Fixed`, measured once from a prototype**, because a cell *widget* contributes nothing to `ResizeToContents` and with no header item either there would be nothing left to measure — the columns collapse. The row height comes from the same measurement, since a row sized from the summary's text squashes both a picker and a button. And **every glyph and swatch is painted, never lettered** — Windows offscreen resolves no font, so a character there is a guaranteed blank — with a hairline round each swatch, since Paper on a light theme is otherwise an empty cell and that is what the *default* swatch means.

**Nothing writes a highlight rule back that the reader did not edit, and `AxisEditor::criteria()` is the trap** (`ARCHITECTURE.md` §5.1, §7.5.4). `HighlighterPane::refreshTimeBounds()` took the whole of `criteria()` into the selected rule whenever the timestamp column's terms moved — and `criteria()` is NOT the inverse of `setCriteria()`: a `QDateTimeEdit` always holds a datetime, so a rule with no bounds reads back as `2000-01-01`, and a value axis that is switched off loads under `ListRule::Unstated`, which ticks nothing, so `allChecked()` reads it back as covering nothing. Both are in `MatchCriteria::operator==`, so merely clicking a run row — or a followed log RESTARTING, through `followLastRunIfMoved()`, with nobody touching anything — rewrote this log's seeded rules, lit the Highlighters marker, put the rewrite on the `Document` and saved it in the session, with no gesture in the application able to restore the seed (`fromJson` yields an invalid bound only from an empty ISO string). Four things are easy to undo. Only `start`/`end` are written, only where the stored bound was **already valid**, and the conversion is done on the STORED wall clock (old zone → instant → new zone) rather than read out of the editor. It is keyed on the **display zone** and never on the mode or the seconds baseline — `Document::recomputeDisplayZone()` leaves the zone alone for `AsWritten`/`EpochSeconds`/`RunSeconds`, so a run selection and an As Written ↔ Seconds switch correctly write nothing. It runs over **every** rule and not the selected one, because `resolve()` reads every rule's digits in the current display zone and a rule left behind silently comes to name an instant hours away (that half was a second, unreported bug: a zone change re-pointed every time-bounded rule EXCEPT the one on screen). And `commit()` is called **only when a rule actually moved**, since this function is on the ingest path. `AxisEditor::coversAllFor()` closes the other half where it starts: an axis switched off with nothing ticked covers everything — what it was loaded with, and what `fromJson` infers from an empty name list — so an ordinary edit to another axis of the same rule stops writing `loggerCoversAll: false` over an empty list. The regression tests assert `doc->highlighters().rules == HighlighterSet::defaults().rules`, never the marker alone: the marker would be satisfied by a patch that repaired only the bounds.

**The Highlighters tab's marker means "these are not the seeded rules", and the comparison under it must stay complete** (`SPEC.md` §7, `ARCHITECTURE.md` §7.5.4). `HighlighterPane::hasCustomRules()` compares the whole rule list, IN ORDER, against `HighlighterSet::defaults()`. It was `!m_rules.isEmpty()`, which every log satisfied from the moment it opened once the three default rules shipped — a marker that is never absent carries no information, and it had consumed the one signal that used to say somebody had set rules on this log. The name moved with the meaning deliberately: a `hasRules()` answering false while three rules colour the log is a trap for the next reader. Four things are easy to undo. **`HighlightRule::operator==` and the `MatchCriteria`/`TextFilter`/`TextMatcher` operators under it compare EVERY field of their structs**, and a field added to a rule but not to the comparison is invisible — editing it simply stops lighting the marker, with nothing to see; `tst_highlight::aRuleDiffersWhenAnyOneFieldOfItDoes` is one case per field for exactly that reason. `updateActivity()` now runs from **`commit()`** as well as from the table rebuild, because unticking or recolouring a rule moves the answer without moving the row count. **An EMPTY list is a difference and IS marked** while **no document is not** — deleting the seed is a choice, and the only thing that explains a log whose ERRORs are not red. And order counts, first-match-wins being per action, so a reorder is a difference.

**A swatch previews the rule's PAIR, and `updateColourPreviews()` is the only place one is made.** Both pickers draw the letter in the rule's text colour on a tile of its background; only which half the entry varies differs, so an entry shows what a matching record would look like if it were chosen. The traps: the counterpart colour must be the **resolved** one (`roleColour()` falls *default* back to `palette().text()`/`palette().base()`, the same fallback `LogView` paints with) or the preview shows something the record never gets; the repaint covers **both** pickers and hangs off the combo's own `currentIndexChanged`, never off `refreshRow()`, whose other callers are axis edits; `makeSwatchCombo()` adds items with **no icon**, so anything that builds a picker without calling `updateColourPreviews()` ships two blank cells (the closed combo clears its text); and the `kDefault` entry keeps its struck-through empty tile rather than being previewed, because previewed it is indistinguishable from Ink or Paper while the one thing it has to say is that it names no colour. Both closed swatches therefore show the same pair, and what says which role a picker sets is the **shape of the tile** — the text picker fills its icon edge to edge and puts a bar under the letter, the background picker draws an inset, rounded **chip** with a margin round it. The bar alone was the cue and was not enough, measurably: it is drawn in the *text* colour, so a rule whose two colours are the same tone rendered the two 14 px icons **pixel-identical** (0 of 196 differing), where the chip's margin owes the pair nothing and takes that case to 136. `kDefault` takes the same two shapes, struck through, so the roles are told apart at the entry with no colour to show. Nothing about it moves a width: `kGlyphPx` is what the prototype measurement sizes the pickers, the fixed columns and the row height from. `tst_highlighterpane::theTwoPickersAreTellableApartAtTheSizeTheyAreDrawn` pins the counts at the size the row draws.

**A log now opens with FATAL, ERROR and WARN already coloured, and the whole difficulty is that a default which comes back after being deleted is a bug nobody can get rid of** (`SPEC.md` §7, `ARCHITECTURE.md` §7.5.4). `HighlighterSet::defaults()` is three colour-only rules on the priority axis — FATAL/Vivid Red, ERROR/Deep Red, WARN/Soft Amber, each foreground being `readableTextSlot()` of its own background so the 4.5:1-in-both-themes pairing is structural rather than checked. Five things are easy to undo. The seed enters at the **two `MainWindow` sites that make a `Document`** — `openWithSettings()` and `prepareContext()` — and **not in `Document` itself**, because "has anything ever been stored for this log?" is a question core cannot ask, and a core seed would colour every document every test builds. The restore asks **`d.highlighters.contains("rules")`, never the array's emptiness**: a stored empty list is the user having deleted every rule and must stay deleted, and reading it as silence re-seeds on every launch — the same trap `fromJson` records for `"actions"` and the settings tree for `"pattern"`, now three stores deep. The rules are ordered **FATAL, ERROR, WARN** because the priority axis is a **minimum**: the ERROR rule matches FATAL too, so swapping the first two hands every FATAL record the ERROR colour, silently and only on logs that have one. Each carries **`Color` alone** — a default that marked tabs or raised desktop notifications would be loftail interrupting somebody before they had opened the pane — which is also why nothing serializes differently and **no schema version moves**: `toJson` already omits `"actions"` for a colour-only rule. And **no gate is needed for a format with no `%p`**: every record is then `Priority::Unknown`, which `AbsentField::DoesNotMatch` already refuses to colour. `tst_sessiongui::aDeletedDefaultRuleStaysDeletedAcrossARelaunch` fails on the `isEmpty()` spelling and is the one that matters; the rules themselves are pinned in `tst_highlight`.

**Presets are a build option now, off by default, and three things about the gate are easy to undo.** The pane docks are tabbed through a **cursor** (`lastTabbed`), not a written-out `filter→highlight→preset→run` chain: spell the chain out and deleting the middle link strands the Runs pane in its own dock area rather than the tab group — a layout that reads as a rendering bug, not as a missing feature. `tst_panechrome` turns on the **count** of the pane docks as well as their names (it identifies the pane tab bar by `bar->count()`), so both come from one build-aware helper and neither may be written out. And **`AtomicJson` stays ungated** — `HostBookmarkStore` writes through it too; it sat next to `PresetStore` only because they shipped in the same milestone. Nothing else in `MainWindow` needed a gate: `addPaneDock()` feeds `m_paneDocks` and every consumer iterates it, and the presets pane is the one pane with no signal connections at all. A saved pane layout crosses the gate **in both directions** with no handling — `restoreState()` keeps a placeholder for an unrecognised dock name, which is also what gives the pane back when the option is turned on again, so do not "clean up" a stale `presetsDock` entry out of the blob.

**Changing a filter no longer moves the reader** (`SPEC.md` §6, `ARCHITECTURE.md` §7.1.2). Neither coordinate a view holds survives a re-apply — the scroll value is a line index in the view's own line space, which the compact `FilteredIndex` remaps wholesale, and `m_current` is a view row that `handleModelReset()` clears — so the anchor is expressed in **source ordinals**, the one coordinate a refilter does not move, by a `LogView::beginFilterUpdate()`/`endFilterUpdate()` bracket that `MainWindow::applyFiltersFor()` puts around the model reset it already did.

**Five rules in it that are easy to undo by accident.** The bracket sits **outside** the reset, and only around a **filter** re-apply: `QItemSelectionModel` clears itself from the same `modelReset` signal (connected before `handleModelReset`), so a restore inside the reset is undone by it — and every other reset (rotation rescan, resume from waiting, digest republish, `setViewIndex`) replaces the record space, where a source ordinal means something else or nothing. `viewRowAtOrAfter()` is a **binary search and means nothing over the digest**, whose ordinals `publishDigest()` reorders by timestamp, which is why `FilteredIndex` carries `m_ascending` and `viewRowOf()` falls back to a scan; `popLastVisible()` leaves the flag alone on purpose, because a conservative false costs a scan and never a wrong answer. The order is **selection → geometry → target line → scroll**: in `SelectedRecordOnly` the selection *is* part of the line space, so a target computed first is computed against a different mapping than it is applied to, and the anchor row lands short by the selected record's extra wrapped lines (`tst_logview::theWrappedSelectionIsFoldedInBeforeTheViewIsRepositioned` is the only test that fails on it, and it fails on nothing else). The follow guard is a **flag, never a `QSignalBlocker`** — the clamp `endResetModel()` provokes used to re-attach follow on a detached view in silence, but blocking the scrollbar suppresses `rangeChanged`, whose connection to `QAbstractScrollArea::_q_showOrHideScrollBars()` is **queued**, so the scrollbar's visibility would stop tracking exactly the range a filter change moves. And `handleModelReset()` keeps its `m_estimated.clear()`: `geom()` returns `FilteredIndex::m_compact`, whose **address is stable** across `setVisible()`, so `ensureEstimatorBound()`'s identity test never rebinds on a refilter — and its tail sync cannot help, because a refilter replaces the record space rather than growing it.

**Apply and Return are the ONLY things the Runs pane applies a pattern from, and the two checkboxes are editors like the field** (`SPEC.md` §3a, `ARCHITECTURE.md` §7.3). `Regex` and `Case sensitive` were connected to `emitPattern` as well as to `updateApplyNote`, so ticking either one applied whatever half-typed pattern was standing in the field: it re-split and re-read the whole log, **persisted** that pattern into the log's settings node (`onRunStartChanged` calls `persistFormat()` before `setRunStart()`, so it survived a restart) and **discarded a pinned run**, since a re-detect defaults back to the newest — the one state `SPEC.md` §3a says only the user moves. The comments that stood over those two lines positively asserted the behaviour as intended, which is why they went with them: this is the one pane whose edits are not live, and a comment saying otherwise is how it comes back. Two things follow. `updateApplyNote()`'s three-way comparison is **load-bearing, not redundant** — a tick is now reported by the note and by nothing else, so dropping `m_regex->isChecked() != m.isRegex()` or its `m_case` twin leaves a control whose change the pane never mentions and Apply then silently acts on. And both boxes carry object names (`runStartRegex`, `runStartCase`) because they had none: `Regex` and `Case sensitive` are `tr()`'d prose, so without them no regression test could reach the widgets at all. `tst_runpane` pins it at three levels — no signal leaves the pane, and through a real `MainWindow` that the log is not re-split, that `logsettings.json` gains nothing until Apply, and that a pinned run stays pinned.

**The Runs pane opens on "Last run", which is a MODE and not a run** (`SPEC.md` §3a, `ARCHITECTURE.md` §7.3). Row 0 of the run list is a standing instruction to show whichever run is last, so a log that restarts takes the view with it; picking a run — including the one that happens to be last — pins it instead, which is the "stay on current run" behaviour the spec used to describe for everybody. Five things are easy to undo. The mode is `Document::m_followLastRun` and **must not be inferred from `selectedRun() == runs().size() - 1`**: those agree exactly while following is working, and telling them apart is the whole feature — `RunPane` asks `followingLastRun()`, and row 0 travels as `RunPane::kLastRun`, never as the ordinal it currently resolves to. `updateRunsAfterAppend()` deliberately does **not** retarget: the append is mid-flight there and the frozen boundary is what stops two runs' records mixing, so the move is `MainWindow::followLastRunIfMoved()`'s, once per tick, and it is a whole re-apply plus a digest rebuild. That call sits **above** the ingest handler's `ctx != activeContext()` early return, or a log that restarts in a background tab sits on the finished run until something else re-applies it — the M19 trap again, and `tst_lastrun` fails on exactly that line. The session saves the mode by saving **no offset at all** (`runAll` false with `selectedRunStartOffset` -1, which already meant "fall back to the last run"), so no schema version moves and a saved session cannot come back pinned to a run that has since finished. And **no runs means the whole file**, not an empty view: the mode is inert until a marker turns up, which is what keeps it safe as the default for every log with no run-start pattern.

**Find says which match of how many, and says when it wrapped** (`SPEC.md` §5, `ARCHITECTURE.md` §7.1.3). A successful find used to set the bar's label to an *empty string*, so a hit and a search that had not run yet looked identical, and F3 at the last match teleported to the top in silence. Four things are easy to undo. The count is `Find::tally()` and is **bounded by rows and by wall clock**, because counting matches decodes every visible record (invariant #1) over every visible column and Find re-runs on every keystroke in the query box — unbounded, that is seconds per keypress on a four-million-record log. `Tally::complete` false must render as `47+`, never as `47`. `Tally::index` is **0 when the scan never reached the hit**, which is the ordinary case on a large log since the scan starts at row 0, and the bar then says `match` with no numbers — a position inferred from `total` would be wrong every time. The wrap is derived from `from`, **captured before `setCurrentRecord(hit)`**: re-read `currentRecord()` afterwards and the comparison is the hit against itself, which reports every search as a wrap. And the report goes in the **Find bar's own per-view label**, never the window status bar, which `updateStatus()` rewrites on every ingest tick and every tab switch. A fifth joined them later: an **empty query answers only a deliberate navigation**, and which of the two cases it is, is exactly `runFind()`'s `fromStart` — false for F3, Shift+F3, Enter and the two arrow buttons, which now report `no search text` instead of nothing at all; true only when the query itself changed, where the reader has just deleted their own text and a message is a nag. Collapse the branch either way and one of the two goes wrong silently. **Find, Find Next and Find Previous are enabled on `hasFile` and on nothing else** — deliberately not on the query being non-empty, because a disabled `QAction` swallows its shortcut with no feedback and gating them would delete the only place that can give that answer.

**The Find bar's status may not take width from the query box, and that is the whole of why it carries `QSizePolicy::Ignored` plus a stretch share** (`SPEC.md` §5, `ARCHITECTURE.md` §7.1.3). The bar is one row — `Find:` · query box · ▲ · ▼ · Regex · Case · status · ✕ — and the box was its only stretch item, so every pixel the wording grew by was taken from the box and every control after it slid left by that much: 114 px between `2 of 2` and `1 of 2, wrapped to the top`, at every window width, since the surplus goes to the stretch item however much there is. The wrap note appears exactly when the reader is stepping through matches with ▼, so it walked the **Case** checkbox under a stationary pointer and the next click restarted the search case-sensitively. Four things are easy to undo. `Ignored` is what drops the label's width out of the layout's sum (`QWidgetItem::sizeHint()` reports 0 for it), and it **must not be paired with `setMaximumWidth`** — that is the Filters pane's context-spinner overlap, recorded above; the share (box 3, status 2) is the whole mechanism. A **minimum** width sized to the longest wording is not a fix and was considered: a `QLabel`'s hint grows past a floor, and there is no longest wording, the match count being unbounded (`128 of 4096+, wrapped to the bottom` is 210 px against 146) with `tr()` on top. The elision is **`ElideMiddle`**, for the reason a crowded tab label is shortened in the middle — `1 of 7` at the front and `wrapped to the top` at the back are both things the reader does not already know, and eliding right takes the wrap note away — with the full text on the tooltip only when it was actually cut. And **`FindBar::status()`, never the label's text, is what the report IS**: the label holds a rendering of it, so a test that reads the label is asserting on the bar's width. `tst_find::theControlsDoNotMoveWhenTheStatusTextChanges` pins it on the child **rectangles** at two bar widths, in the shape of `tst_filterpane::theContextRowLaysOutWithoutOverlapOrClipping` and for the same reason: every widget existed, was visible and held the right value — only its position was wrong.

**Every report `runFind()` makes must land somewhere visible, and the reveal PRECEDES the report** (`SPEC.md` §5, `ARCHITECTURE.md` §7.1.3). The Find bar is a `DocumentView` child that starts hidden; F3 and Shift+F3 are `MainWindow` actions that fire from anywhere, Escape closes the bar without touching the query, and every branch of `runFind()` — `no search text`, `bad regex`, `no records`, `no match` and the match-and-wrap report — answers into that bar's own label. So a search ran, the cursor moved and the marks came back over a bar nobody could see. `runFind()` now opens with `FindBar::reveal()`, above every branch, and four things about it are easy to undo. It is **`reveal()` and not `activate()`**: `activate()` (Ctrl+F) begins with `setStatus(QString())`, so revealing through it — or revealing after the report is written — replaces the silence with a **blank** bar, which is worse because it looks answered. `reveal()` **must move the focus**: Escape is handled in `FindBar::keyPressEvent` and the bar is a **sibling** of `LogView` under `DocumentView`, not an ancestor, so an Escape at the table propagates `LogView` → `DocumentView` → `MainWindow` and never reaches it — a bare `show()` ships a bar closable only with the ✕ button, and nothing about `status()`, visibility or marks can see that (`tst_find::escapeStillClosesTheBarThatFindNextRevealed` is what can). It is a **no-op on a bar already open** (`isHidden()`, not `isVisible()`, which is additionally false for an unshown window), which is what keeps `no match` and the successful find leaving focus and selection alone — `:2912`'s "focus stays in it for the next F3" depends on it. And **Ctrl+F still searches nothing**: a reopened bar shows the standing query selected for replacement, with a blank report and no marks, because re-running would move the reader's cursor on a gesture that only asked for a box, and marking without searching is a mark with no hit behind it. **Every case in `tst_find` asserted on `status()` alone, which is exactly how this shipped** — a report written into a hidden bar satisfies that perfectly — so the new cases assert `isVisible()` too and drive a real `QTest::keyClick(&w, Qt::Key_F3)` rather than `trigger()`ing the action.

**Find now marks the matched run, and the whole design is that NOTHING is held** (`SPEC.md` §5, `ARCHITECTURE.md` §7.1.4). A match position is per record, per column and per query, so `LogView` keeps the **query** — the very `TextMatcher` `runFind()` searched with — and re-runs it over the cells it is painting anyway, which the paint path had already decoded (invariant #1). Every match in view is marked, not only the record the search landed on, and the mark is that run in the record's **own two colours swapped**: whatever contrast the record had — a rule's `PaletteSlot` pairing, the theme's, the selection's, a context row's dimmed pair — the run has exactly, in both themes, with no new palette entry to drift. Six things are easy to undo. The positions come off `TextMatcher::spans()`, which sits beside `matches()` and reads the same compiled regex and case option — **write a second matcher and a mark starts disagreeing with a hit**, which is worse than no mark. The glyphs are redrawn by the **same call, clipped**, never re-positioned at a measured offset: re-shaping a fragment out of its context is how glyphs drift out from under the patch. `drawWrappedCell()` lays the text out itself with a `QTextLayout` — which is what marks a match **straddling a wrapped line on both lines** — and it now does so for **every** wrapped cell rather than only for a record that matches, because the layout and the `drawText` it used to fall back to do not break lines alike (see the paragraph below); the estimated/exact geometry seam is untouched by any of this. A mark over an elided cell is computed on the string **as drawn**, so a match past the ellipsis is not marked rather than pointed at with arithmetic about how wide "…" is. The spans are **capped per cell** (`kMaxCellMarks`) and zero-width regex matches yield none, because a one-character query over a hundred-thousand-character message is otherwise a mark per character on the paint path. And the **digest strip is never armed** — `runFind()` reaches `activeLogView()` only, so a mark there cannot claim the search landed in the strip; the matcher is cleared on an empty query, a bad regex, no records and no match, and by `DocumentView` when the bar closes.

**A mark is drawn by re-issuing the cell's own draw call, and that call draws the WHOLE cell — so every run of one cell goes into one `QRegion` and the redraw is issued ONCE.** Per run it was O(runs × display lines) whole-paragraph redraws, and the trap is that both multipliers are **capped rather than small**: `kMaxCellMarks` is 64 and `RecordIndex::kDisplayLineCap` is 100, so a single-letter query — the ordinary thing to type — took one repaint of one wrapped record from 1.4 ms to 17.4 ms, on every scroll, resize, ingest tick and tab switch. The cap is what makes the 64× multiplier *reachable* rather than unbounded; it is not what makes it cheap, and `60b4aa5`'s own cost contract ("one `spans()` call per already-decoded string and nothing else") was true of the search and false of the paint (`bugs.md` 12). Three things are easy to undo. Every rectangle is **filled before anything is redrawn** — a fill issued after a redraw erases the glyphs of the run it lands on, which the per-run loop got right only because each redraw immediately followed its own fill. The redraw stays **one call over the union**, never `QTextLine::draw()` per line: the per-line form is just as fast and is *not* pixel-identical, because a patch also catches ink overhanging from the neighbouring line and only the whole-layout call puts it back — `lineHeight()`'s `ceil` means the primary face never overhangs, so that is the fallback-font case (CJK, emoji) and nothing else. And `drawElidedCell()` places its runs with a **`QTextLayout` and `cursorToX()`, never `QFontMetrics::horizontalAdvance()`**: a sum of per-character advances is the *logical* width of a prefix, which is the run's visual left edge only for a single left-to-right run — over Arabic or Hebrew the mark covered 62% of the match and sat over the wrong glyphs. That also took two O(prefix) shaping passes per run out of the paint path. `tst_logview::aMarkedCellIsRedrawnOncePerCellAndNotOncePerMatch` **counts the draws** through a paint device that tallies what the painter asks of it rather than asserting on a wall clock, and fails the unfixed code at 2112 text runs against 35 unmarked.

**The two wrapped-cell renderings must break lines identically, and no `drawText` flag pair reaches `WrapAtWordBoundaryOrAnywhere`** (`SPEC.md` §5, `ARCHITECTURE.md` §7.1.1, §7.1.4). `drawWrappedCell()` used to be `QPainter::drawText()` with flags when there was nothing to mark and a `QTextLayout` when there was, on a documented mapping from `Qt::TextWordWrap | Qt::TextWrapAnywhere` to `QTextOption::WrapAtWordBoundaryOrAnywhere`. **Qt honours no such mapping** — `TextWrapAnywhere` wins, the pair behaves as plain `WrapAnywhere`, and *no* combination of `drawText` flags produces word-boundary wrapping — so typing one character into Find re-flowed the record the reader was in the middle of, and where the layout wanted more lines than the height model had given the record, the extra ones were clipped away with nothing on screen to say so (a wrapped message is deliberately not elided and offers no tooltip). One function, `layoutWrappedText()`, now lays every wrapped cell out and `measureWrappedLines()` counts through it. Four things are easy to undo. **The wrap mode still differs per rendering**: `AlwaysOn` is `WrapAnywhere` — §7.1.1's whole height model is `ceil(chars / cols)`, which only a character wrap satisfies — and `SelectedRecordOnly` is `WrapAtWordBoundaryOrAnywhere`, which is what "read this one record in full" means and what `SPEC.md` §5 now promises. **A tab is laid out as one blank**, by substituting a space into the paragraph string: a `QTextLayout` advances U+0009 to a tab stop, 80 px by default and about eleven columns at the reference face, where `drawText` gave it one character's width and where the height model counts it as one — so a TAB-indented stack trace re-flowed and lost its tail under *Always On* too, which is the mode entry 4 never touched. The substitution is one character for one, so every `TextMatcher::Span` offset still means the character it meant. **`measureWrappedLines()` may not go back to `QFontMetrics::boundingRect()`**: no flag it takes measures word-boundary wrapping, so counting through the layout is the only way the exact path's height and its text can agree. And the whole thing is only observable in **pixels** — every widget holds the same values marked or not — so `tst_logview::aTabbedRecordBreaksWhereItAlwaysDidWhenFindIsArmed` and `theSelectedRecordBreaksWhereItAlwaysDidWhenFindIsArmed` render the viewport twice and compare where each line box stops inking. Both must settle the viewport geometry with a render **before** measuring the wrap width, or the width they aim at is one the view never had.

**Copying a selection re-enters the event loop, and that is the trap on the copy path** (`SPEC.md` §5, `ARCHITECTURE.md` §7.1.6). Both copy commands now walk the selection as **ranges** (Select All is one range, not four million `QModelIndex`es), append into **one reserved `QString`** rather than a list that is then `join()`ed, and above `copyProgressThreshold()` records run in chunks behind a cancellable **application-modal** progress dialog. The modality is load-bearing, not decoration: it is what makes "the view cannot be destroyed under the walk" true, so the dialog is shown **before** the first `processEvents()` rather than after `QProgressDialog`'s own `minimumDuration`. A **model reset** abandons the copy (a view row now means a different record), an **append or tail removal does not** — every row is re-resolved through `sourceRow()` and bounds-checked as it is read, and abandoning there would make a long copy impossible on a live filtered log, which removes and re-adds its provisional row every tick. `setAutoReset(false)` matters for one reason: `reset()` clears the flag `wasCanceled()` answers, so with the default a Cancel pressed on the last chunk is forgotten. And the clipboard is written **once, at the end** — that, not care, is what makes a cancelled copy leave it untouched. Below the threshold there is no dialog and no event processing at all, which is why every other test in the tree is unaffected.

**Outstanding regardless of milestone:** Windows and macOS builds and runtime behavior are still unverified beyond what CI asserts (`PLAN.md` M6/M7). **M6's two Windows stubs are both gone** — the share-mode open and `pathIdentity()`, below — so what is left is the part no test speaks for: how the application behaves under a person on that platform.

**The Windows share-mode open is no longer stubbed, and what it cost is the lesson.** `BufferedLogSource` held a `QFile`, whose Windows open passes `FILE_SHARE_READ | FILE_SHARE_WRITE` and **not** `FILE_SHARE_DELETE` — so for six milestones, a log open in a tab could not be rolled or deleted by the process writing it, which is invariant #5's second clause failing on the one platform this source is *for*. It hid because **appends were never blocked**: the operation the read path exercises all day is the one the missing bit does not touch, so every read-path test passed on Windows throughout. The open is now `SharedReadFile` — `CreateFileW` with all three share bits on Windows, `QFile` everywhere else, the only file in the tree that includes `<windows.h>` deliberately. `BufferedLogSource` keeps its own `m_path` because a handle carries no name: route `wasReplaced()`, `originVanished()` or `computeIdentity()` back through the handle and they answer about nothing. What caught it was a **test that deleted a log while a window had it open** (`tst_reload::reloadingAVanishedLogWaitsForItRatherThanFailing`, M-reload), the first anywhere to do that on Windows — `tst_tail` and `tst_waiting` are both POSIX-only and their CMake entry had said the Windows sharing semantics "must be exercised separately (not done yet)" since M6. `tst_sharedreadfile` is that, ungated: it asserts that appending to, renaming and deleting an open log all still succeed, which is free on POSIX and was not on Windows.

**M6's other Windows stub, `pathIdentity()`, is gone with it, and it had been silently costing rotation detection.** It returned 0 unconditionally there, so `wasReplaced()` was **always false** and a rolled log kept the old file's records until the size happened to shrink or the first kilobyte happened to differ — for eight milestones. It is now volume serial + file index from `GetFileInformationByHandle`, folded the same way POSIX folds device + inode, and it lives in `SharedReadFile.cpp` **beside the read open, not in `LogSourceFactory.cpp` where it was**: Windows will only give a file's identity through a handle, so this is a second `CreateFileW` — and it carries the same discipline, with `FILE_READ_ATTRIBUTES` (which succeeds even on a file opened for exclusive writing) and again all three share bits. That last part matters MORE here than in `open()`: this runs on **every watch tick**, so a stingier share mode would block the writer's roll for a moment every 750 ms and intermittently break the very rotation it is called to detect. Three rules are easy to undo. **0 means unknown, never "replaced"** — every caller guards on `current != 0 && captured != 0`, because the gap between a roll's rename and its recreate is exactly a 0 and reading it as a difference rescans against a file that is not there yet. **A ReFS volume reports index 0**, whose 128-bit id does not fit, and that is answered as unknown rather than as a value every file on the volume would share — one false identity is worse than none, since it matches across different files as well as missing a real rotation. And the identity is re-resolved **from the path**, never read off the handle the source already holds: a handle follows the file it opened, which is precisely why a rotation is invisible to it. `tst_pathidentity` is ungated and drives all of it at the source level — where the platforms differ and where the stub was — because `tst_tail`, which drives the same question through `LiveController`, is POSIX-only for reasons that have nothing to do with identity.

**Windows testing has no fonts.** The offscreen QPA plugin on Windows uses Qt's own font database, which looks in `$QTDIR/lib/fonts`; Qt no longer ships fonts, so `QFontDatabase::families()` comes back **empty** and nothing resolves — not even to a wrong font. (Offscreen on Linux has fontconfig, so this never shows up locally.) Any test that asserts on resolved font properties must guard on an empty family list and `QSKIP`; `tst_logview::everyColumnRendersFixedPitch` does. This is an environment limit, not a `monospaceFont()` bug.

**Most of it CAN be reproduced on Linux, and the one difference is what makes the reproduction worth having.** Point `FONTCONFIG_FILE` at a config naming an empty directory and the offscreen run gets Qt's last-resort box engine: every glyph is drawn as a filled box the height of the line and every column width comes from `charWidth()`'s 8 px floor, which is the geometry the Windows leg actually fails on — `ctest` reproduces the Windows failures of `tst_logview` and `tst_recordmenu` line for line. What it does NOT reproduce is the guard: fontconfig still reports `Monospace`/`Sans Serif`/`Serif`, so `QFontDatabase::families()` is **not** empty and every test that would `QSKIP` on Windows runs and fails here instead. So a red test under that environment means the Windows leg is red only if the test carries no guard — the environment is strictly harsher, never laxer. Two Windows failures were fixed with no skip at all this way: a case that read the row fill off the rightmost pixel column now narrows the sections first so there is a strip past the last one that no glyph can reach, and one that clicked a cell at its natural position now narrows them to fit the viewport, because the 8 px floor pushes the Subsystem column clean off the right edge of the document area.

**A path written `"/var/log/app.log"` is absolute on POSIX and is NOT on Windows**, where a path with no drive is resolved against the current one — so `logSettingsKey()`, which keys a settings node by `QFileInfo::absoluteFilePath()`, stores `D:/var/log/app.log` on the runner and every expectation spelled the POSIX way misses by a drive letter. It bites exactly where a test compares a **stored address to a literal** (a tooltip, a label); a test that only ever looks the address up through the same key function never notices, which is why `tst_logsettings` is green on the same paths that made `tst_preferences` red. The spelling is `QDir::rootPath() + "var/log/…"`, which is already absolute on both and therefore comes back out of the key unchanged — never an `#ifdef`, and `tst_archivelocation`'s `abs()` helper is the older precedent for the same rule.

**The dev machine's Qt is NEWER than the reference build's, so a green local build proves nothing about the API surface.** Qt 6.10 here, Qt 6.4.2 on Ubuntu 24.04 (`ARCHITECTURE.md` §1) — anything added to Qt in between compiles clean locally and breaks four CI jobs at once. The one that has bitten: **`priorityName()` returns a `QLatin1StringView`, which has no `toUtf8()` on 6.4**, so `priorityName(p).toUtf8()` builds here and fails on the reference toolchain, on the sanitizer job, on the `.deb` job and on MSVC (where it also cascades into a bogus "`QTest::qVerify` does not take 4 arguments", since the failed argument changes the overload). Every caller in `src/` already writes **`QString(priorityName(p))`** — follow it. More generally: a *test* is as exposed to this as `src/` is, and the Qt version gap is checked only by CI, exactly like Windows.

**Windows headers define `min` and `max` as macros.** `std::numeric_limits<qint64>::min()` — `Record::kNoTimestamp`, `FilterSet`'s time bounds — becomes a syntax error in any translation unit that reaches `<windows.h>` before a loftail header. Nothing here includes it directly; **libarchive's public header does**, so the breakage lands on include *order* and only on Windows, which is exactly the rule nobody remembers. The build defines `NOMINMAX` (and `WIN32_LEAN_AND_MEAN`) PUBLIC on `loftail_core` so `loftail_ui` and every test inherit it. This bit M12 in CI, in two test files that included the fixture header first.

**When a Windows test fails, read the CI diagnostic, not the ctest output.** Test output does not reach ctest on Windows — a failure shows as `***Failed` with an empty block, which reads like a crash and is not. The Windows job re-runs each failed binary one test function at a time, prints per-function exit codes, and dumps QtTest's report via `-o file,txt` for the failing one. That is where the actual assertion appears.

## What loftail is

A cross-platform (Windows/macOS/Linux) desktop GUI viewer for logs produced by **log4cplus**. Every file is opened watched for new content, so it serves finished logs and still-being-written logs with no mode switch (`SPEC.md` §3). It filters and highlights by subsystem (the logger name passed to `Logger::getInstance()`) and priority, with saved presets and full session restore.

## Stack

- **C++20**, **Qt 6** (6.10 is installed on the dev machine; target 6.4 minimum — the version in Ubuntu 24.04's repos)
- **Qt Widgets**, not QML — see `ARCHITECTURE.md` for the rationale; the decision is load-bearing and should not be revisited casually
- **CMake ≥ 3.21** + **Ninja**
- **libssh2**, optional and auto-detected, for remote logs (M11). The build must keep working without it — configure prints `SSH remote sources: ENABLED/DISABLED`. `-DLOFTAIL_WITH_SSH=OFF` forces it off; `-DLOFTAIL_SSH_FETCH=ON` builds it from source (used by the Windows CI job, which has no package manager)
- **libarchive**, optional and auto-detected, for compressed and archived logs (M12). Configure prints `Archived log sources: ENABLED/DISABLED` and `-DLOFTAIL_WITH_ARCHIVE=OFF` forces it off. **It has no build-from-source fallback, unlike `LOFTAIL_SSH_FETCH`, and deliberately so:** libarchive is only useful *with* its codecs, and it locates zlib and liblzma through `find_package` in **MODULE** mode, which `CMAKE_FIND_PACKAGE_REDIRECTS_DIR` does not reach — so a FetchContent-built codec is silently ignored, libarchive builds with no compression at all, and still reports itself found. That failure is invisible until a `.gz` refuses to open. Get it from a package manager (`libarchive-dev`, `brew install libarchive`, `vcpkg install libarchive`); the Windows CI job uses vcpkg. A **static** libarchive additionally needs `-DLOFTAIL_ARCHIVE_STATIC=ON`, or its `__declspec(dllimport)` API links against import stubs that do not exist
- **QtKeychain**, optional and auto-detected, for storing remembered SSH passwords in the OS keychain (M14). Configure prints `OS keychain for passwords: ENABLED/DISABLED` and `-DLOFTAIL_WITH_KEYCHAIN=OFF` forces it off; without it a remembered password falls back to plain text in `hosts.json`, exactly as it did before, and the dialog says so. One dependency covers KWallet and GNOME Keyring (through the freedesktop Secret Service), the Windows Credential Manager and the macOS Keychain. `-DLOFTAIL_KEYCHAIN_FETCH=ON` builds it from source — **and that fallback is right here where it was wrong for libarchive**, for the mirror-image reason: QtKeychain has no codecs to silently lose, on Windows it is a thin wrapper over the Credential Store with no external dependency, and the Windows CI job needs it because that runner has no package manager and vcpkg's `qtkeychain-qt6` port drags in vcpkg's own qtbase and qttools. Get it from a package manager otherwise (`qtkeychain-qt6-dev`, `brew install qtkeychain`)
- **Presets** are behind `-DLOFTAIL_WITH_PRESETS`, **OFF by default** (M5's feature, gated later). Configure prints `Presets: ENABLED/DISABLED`. It is the one gate that is a *feature* switch rather than a dependency probe — there is nothing to auto-detect, so unlike the three options above it defaults off and `LOFTAIL_HAVE_PRESETS` merely mirrors `LOFTAIL_WITH_PRESETS`. **No CI leg builds it**, so `PresetPane.cpp` and `tst_presetstore.cpp` will rot: build and test `-DLOFTAIL_WITH_PRESETS=ON` by hand before committing anything that touches `FilterPane`/`HighlighterPane` state serialisation
- **Qt Linguist tools**, optional and auto-detected, only to produce `.ts` files. Configure prints `Translation tooling: ENABLED/DISABLED`, and when found adds a `loftail_lupdate` target that nothing depends on. No catalogue ships and `translations/` is git-ignored — see `ARCHITECTURE.md` §9.1
- **Qt Test** for unit tests
- **Reference build environment is Ubuntu 24.04 LTS**: the project must build with the stock toolchain (GCC 13, CMake 3.28, Ninja, Qt 6.4.2) using no separately-installed Qt. This is why the Qt minimum is 6.4, not 6.5 LTS — see `ARCHITECTURE.md` §1.

loftail does **not** link log4cplus. It reads log files as text; it has no compile-time relationship to the library that produced them.

## Architecture invariants

These ten constraints are cheap to honor from the start and expensive to retrofit. Do not violate them without explicitly reopening the decision.

**loftail does not link log4cplus, and links exactly three other non-Qt libraries** — libssh2, libarchive and QtKeychain — all optional, all auto-detected, and the build must stay green without any of them.

1. **The model stores byte offsets, never parsed text.** A record entry is `{offset, timestamp, length, loggerId, threadId, lineCount, priority}` — exactly 32 bytes. Message text is parsed lazily inside `data()`. Holding parsed strings for every record makes large files unusable.

2. **A record is not a line.** log4cplus messages can contain embedded newlines, so one record may span several physical lines. Indexing rule: a line matching `recordStartRe` begins a record; non-matching lines are continuations of the preceding record. Code that assumes one-line-per-row is wrong.

3. **Nothing downstream of the parser knows about the pattern string.** `PatternCompiler` turns a log4cplus `ConversionPattern` into a `LogFormat` (regex + field map). Views, filters, and highlighters consume only the field map. This indirection is what makes format autodetection (a later-release feature, `FUTURE.md`) a drop-in rather than a rewrite.

4. **Filtering compares integers, not strings.** Logger and thread names are interned to `quint32` ids at index time; priority is an enum **declared in severity order** so filtering by minimum level is one `>=` test (`ARCHITECTURE.md` §7.2); timestamps are `qint64`. Filter predicates operate on those. The intern tables double as the subsystem and thread lists shown in the filter pane. Message-text filtering is the one axis with no integer fast path, so it runs last in the predicate chain — including on the paint path, where highlight rules use the same axes and the same lazy-decode ordering.

5. **Every file is opened append-aware; there is no post-mortem vs live mode.** loftail cannot know whether a file is still being written, so all files are watched and a finished log is just one that never grows (`SPEC.md` §3). No `LogSource` may assume the file is immutable, and none may hold it in a way that blocks the writer from appending, rotating, or truncating — observing a log must not disturb the process producing it. File access goes through the `LogSource` interface; the model cannot tell which implementation it has — local or remote. The mmap (POSIX) vs buffered (Windows) split is platform-driven, not mode-driven (`ARCHITECTURE.md` §6); a remote or archived log reads through a local spool that one of those two then backs (§6.3, §6.4). Rotation is asked of the source via `wasReplaced()`, never worked out by the caller: what has to be re-resolved differs per source. **The one permitted exception, added in M12:** a source may declare its stream finished via `isComplete()` — but only where loftail *produced* the bytes itself from a fixed input and can prove there are no more, i.e. an expanded archive member. The ban is on *guessing* that a file somebody else is writing has stopped. Nothing user-facing follows from it: the watch stops because there is no work left, the follow control is untouched, and there is still nothing to turn on or forget.

**Not an exception at all, added in M13:** a source may report that its origin is *gone* via `originVanished()`. That is an **observation, not a guess** — "the file is not there" is what a stat answers, which is exactly why `isComplete()` needs loftail to have produced the bytes and this does not. The document then *waits* rather than erroring (`SPEC.md` §3, §6.5), and the watch keeps running because waiting is the one state in which it is the only thing making progress.

6. **The record table is a custom `LogView : QAbstractScrollArea`, not a `QTableView`.** Multi-line records render at full height, and `QTableView` cannot do variable row heights lazily — it needs an O(n) `resizeRowsToContents()` pass or per-row entries in `QHeaderView`, either of which defeats the lazy index. `LogView` scrolls in *line* units over two-level prefix sums of `Record::lineCount`. It has two geometry modes: **exact** (wrap off / selected-record-only) and **estimated** (wrap always on, where height depends on viewport width). Keep the estimation machinery unreachable from the exact path. See `ARCHITECTURE.md` §7.1–7.1.1; this is the project's highest-risk component.

7. **All per-file state lives in `Document`; all per-view state lives in `DocumentView`; nothing reaches for "the current file" globally.** Several files are open at once and one file may have several views, so the two scopes must not blur: filters, highlighters, format and run selection belong to the *file*; scroll, selection, wrap mode, column layout, follow and find belong to the *view*. No singletons holding file state; panes bind to an `activeDocumentChanged(Document*)` signal rather than a fixed reference, and that signal fires only when the **file** changes, never when switching between two views of one file. The settings schema stores a `documents` array and a `views` array. See `ARCHITECTURE.md` §12.

8. **Never scan for `\n` in raw bytes.** Encoding is user-selectable, defaults to auto-detect, and may be UTF-16, where a newline is `0A 00` or `00 0A`. All line-boundary and text work goes through the `Decoder` layer; only `Record::offset`/`length` stay in byte terms. See `ARCHITECTURE.md` §6.1 — this is the easiest invariant to violate by accident.

9. **The indexer is a single forward pass.** No backward passes, no seek-and-re-read. This is the constraint that let SSH-backed sources ship in M11 as an addition rather than a rewrite: because the indexer never seeks backwards, a remote log's spool can be filled and indexed *at the same time*, which is the whole difference between following a remote log and downloading one. **It paid a second time in M12**, and more visibly: an archived log fills in *as it expands* rather than freezing until it is done, for exactly the same reason. Two features, one constraint — while `isRandomAccess()`, the flag actually designed for this job, remains unread by any branch in the codebase. Random access is fine in `data()` on the paint path, which only touches already-indexed records. See `ARCHITECTURE.md` §6.2–§6.4.

10. **`Record::timestamp` is always UTC epoch milliseconds.** The source time zone and the timestamp display mode are both user-configurable, but conversion happens exactly twice: source zone applied at index time, display zone applied when formatting or interpreting typed filter bounds — or not at all, in the two *seconds* display modes, which render the stored ms directly. Nothing in between is zone-aware. Storing local wall-clock time would make comparisons zone-dependent and break across DST transitions, where the same local time occurs twice. See `ARCHITECTURE.md` §5.1.

## Conventions

- Qt naming throughout (`camelCase` members, `PascalCase` types) so the codebase reads consistently with the framework it sits on.
- Prefer `QStringView`/`QByteArrayView` on parse paths; avoid allocating per record.
- No hardcoded paths — `QStandardPaths::AppConfigLocation` for settings and presets.
- Open log files in binary mode and handle CRLF explicitly rather than relying on platform text-mode translation.
- Parsing and indexing logic must be unit-testable without a `QApplication` instance; keep it free of UI dependencies.
